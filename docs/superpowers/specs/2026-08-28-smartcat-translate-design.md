# SmartCAT Translate 설계 명세

- 작성일: 2026-08-28
- 상태: 사용자 승인 완료, 구현 계획 작성 전
- 제품명: SmartCAT Translate는 작업용 이름이며 공개 배포 전 최종 명칭을 검토한다.

## 1. 목적

Windows와 macOS 어디에서나 선택한 텍스트, 직접 입력한 텍스트, 이미지, 화면 영역 및 문서를 사용자의 ChatGPT 계정으로 번역하는 로컬 데스크톱 앱을 만든다. DeepL과 유사한 간결한 사용 경험을 제공하되, 공식 Codex App Server 인증과 사용자의 Codex 구독 한도를 이용한다.

핵심 목표는 다음과 같다.

1. 전역 단축키로 빠른 번역 창을 연다.
2. 다양한 단축키 조합과 연속 입력을 지원한다.
3. 충돌을 감지하고 원인과 대체 단축키를 안내한다.
4. 텍스트, 이미지, 화면 캡처, DOCX, PPTX, XLSX, PDF를 번역한다.
5. 문서와 이미지의 원래 서식과 배치를 최대한 유지한다.
6. 원본을 수정하지 않고 새 번역 파일을 만든다.
7. Windows와 macOS 설치 파일을 하나의 GitHub 저장소에서 관리한다.
8. 모든 계획, 결정, 변경 및 검증 결과를 추적 가능하게 기록한다.

## 2. 범위

### 포함

- 텍스트 입력, 붙여넣기, 선택 텍스트 번역
- 전체 번역 창과 작은 빠른 번역 팝업
- 이미지 OCR, 번역문 재배치, 원문/번역문 비교
- 화면 영역 캡처, OCR, 번역 이미지 생성
- DOCX, PPTX, XLSX, PDF 번역
- 언어 자동 감지와 복수 언어쌍
- 빠른, 균형, 정밀 품질 설정
- 문체, 분야, 용어집, 보호 용어
- 번역 기록, 시크릿 모드, 로컬 암호화
- 전역 단축키와 앱별 차단 목록
- GitHub Actions 기반 Windows/macOS 빌드 및 릴리스

### 초기 범위에서 제외

- 일반 ChatGPT 대화 기록에 번역을 저장하는 기능
- 비공식 ChatGPT 웹 세션 자동화
- 모바일 앱
- 서버에 별도 사용자 계정이나 번역 파일을 저장하는 기능
- 원본과 픽셀 단위로 완전히 동일한 PDF 재조판 보장

## 3. 기술 기반

### 공통

- 데스크톱 셸: Tauri 2
- 화면: React + TypeScript
- 핵심 처리: Rust
- 번역 연결: 공식 Codex App Server의 표준 입출력 JSONL
- 로컬 데이터: 암호화 가능한 SQLite 계층과 운영체제 보안 저장소
- 자동 빌드: GitHub Actions

### 플랫폼별 어댑터

- Windows: 전역 단축키, 저수준 연속 키 감지, 화면 캡처, OCR, 트레이, 자동 실행
- macOS: 전역 단축키, 접근성 및 화면 기록 권한, Vision OCR, 메뉴 막대, 자동 실행

공통 인터페이스 뒤에 플랫폼별 구현을 배치하여 React 화면과 번역 작업 흐름은 공유한다.

## 4. 구성 요소

### React 화면

- 전체 번역 창
- 빠른 번역 팝업
- 화면 캡처 결과 창
- 문서 작업 진행 창
- 설정, 기록, 용어집, 계정 및 사용량 화면
- 한국어와 영어 UI, 키보드 탐색, 화면 읽기 도구용 이름과 상태 안내

### Rust 서비스

- CodexRuntimeManager: 기존 Codex 탐색, 앱 전용 설치, 버전 검증
- CodexAppServerClient: 시작, 초기화, 계정 로그인, 스레드와 턴, 스트리밍 응답
- TranslationCoordinator: 작업 분할, 프롬프트 작성, 문맥과 용어 일관성
- HotkeyManager: 조합 등록, 연속 입력 상태기계, 충돌 검사, 차단 목록
- CaptureService: 영역 선택, 캡처, OCR, 글자 좌표 정규화
- DocumentService: 형식 식별, 추출, 재조립, 결과 검증
- HistoryService: 설정, 암호화 기록, 보존 기간과 삭제
- JobRecoveryService: 체크포인트, 재시도, 취소, 재개
- AuditLogger: 개인정보를 제외한 개발 및 앱 진단 기록

## 5. Codex 인증과 번역 흐름

1. 앱 시작 시 시스템 경로와 알려진 설치 위치에서 공식 Codex를 찾는다.
2. 호환 가능한 기존 Codex가 있으면 이를 사용한다.
3. 없으면 플랫폼과 CPU에 맞는 검증된 공식 바이너리를 앱 전용 폴더에 설치한다.
4. Codex App Server를 자식 프로세스로 실행하고 초기화한다.
5. 계정 상태를 읽고 로그인되지 않았으면 `ChatGPT로 로그인`을 표시한다.
6. 로그인 시작 요청이 반환한 공식 URL을 기본 브라우저에서 연다.
7. App Server가 인증 토큰과 갱신을 관리하며 앱은 비밀번호나 토큰을 기록하지 않는다.
8. 내용이 없는 기준 스레드에서 메모리 전용 임시 스레드를 포크하고 번역을 실행해 Codex 로컬 스레드 기록에 원문과 번역문을 남기지 않는다.
9. 작업이 끝나면 임시 스레드를 폐기하고 스트리밍 결과만 앱의 암호화 기록 정책에 따라 처리한다.
10. 입력 안의 명령문은 실행 지시가 아니라 번역할 데이터로만 취급한다.
11. 사용량 제한이나 인증 만료가 발생하면 작업 상태를 보존하고 안내한다.

Codex 사용은 사용자의 계정에서 허용되는 모델과 한도를 따른다. API 키 기반 사용은 향후 선택적 공급자로 추가할 수 있지만 기본 경로가 아니다.

### 번역 세션 보안 경계

- 번역 세션은 앱 전용 빈 작업 폴더에서 실행한다.
- 파일 시스템 접근은 앱이 명시적으로 만든 작업 입력으로 제한한다.
- 셸 명령과 코드 실행은 번역 작업에 허용하지 않는다.
- 모델이 도구 사용을 요청해도 앱은 실행하지 않고 오류로 처리한다.
- 각 번역은 `thread/fork`의 `ephemeral: true`로 만든 메모리 전용 스레드에서 실행한다.
- 내용 없는 기준 스레드는 앱 종료 시 `thread/delete`로 제거한다.
- 문서와 이미지는 앱이 텍스트/이미지 입력으로 전달하며 임의 경로를 모델에 노출하지 않는다.
- 프롬프트 인젝션과 도구 호출 시도를 회귀 테스트에 포함한다.

## 6. 단축키 설계

### 지원 유형

- 단일 조합: Ctrl+Shift+C, Cmd+Shift+C 등
- 연속 입력: Ctrl+C 다음 C, 동일 조합 두 번 등
- 기능별 단축키: 텍스트, 화면 캡처, 이미지, 전체 창
- 단축키별 언어쌍과 품질 프로필
- 선택 텍스트를 얻기 위해 복사 동작을 사용할 때 기존 클립보드를 보존하고 작업 후 복원

### 충돌 판정

1. 운영체제 등록 시험
2. 앱 내부 중복 확인
3. 운영체제 예약 단축키 자료 확인
4. 주요 앱의 알려진 단축키 자료 확인
5. 현재 실행 중인 프로그램과 앱별 프로필 비교
6. 원인을 특정할 수 없으면 다른 프로그램이 사용 중이라고 정확히 표시

기본 동작은 등록 차단, 충돌 가능 프로그램과 기능 표시, 대체 조합 추천이다. 사용자가 명시적으로 선택하면 경고 후 강제 등록을 허용한다. 특정 앱에서는 단축키를 완전히 끄는 차단 목록을 제공한다.

## 7. 번역 설정

- 기본값: 원문 자동 감지, 대상 한국어, 균형 품질, 자연스러운 문체
- 원문과 대상 언어가 같으면 번역 대신 문장 개선 모드를 제안
- 품질: 빠른, 균형, 정밀
- 문체: 격식, 일상, 존댓말, 반말, 직역, 자연스러운 번역
- 분야: 일반, 기술, 법률, 의학, 비즈니스 등
- 용어집: 지정 번역, 번역 금지, 고유명사 보호
- 자동 보호: URL, 파일 경로, 코드, 변수명, 제품명
- 계정에서 제공되는 Codex 모델만 표시
- 기본 모델은 작업 크기와 품질 설정에 맞춰 자동 선택하며 사용자가 사용 가능한 모델을 직접 고를 수 있음
- 긴 문서는 구간별로 처리하되 문서 용어표와 앞선 문맥 요약을 이어서 사용

## 8. 이미지와 화면 캡처

1. 이미지 또는 화면 영역을 확보한다.
2. OCR로 문자열, 행, 블록, 좌표, 방향과 신뢰도를 추출한다.
3. 번역 제외 영역과 보호 용어를 적용한다.
4. 구조화된 블록 단위로 번역한다.
5. 원문 영역의 배경을 복원하고 번역문을 원래 위치에 맞춘다.
6. 글자 크기, 줄바꿈, 정렬을 영역 안에서 조정한다.
7. 번역 이미지와 원문/번역문 비교 결과를 함께 제공한다.

결과 동작:

- 번역 이미지 저장
- 원문 복사
- 번역문 복사
- 전체 창에서 수정
- 복잡한 배경이나 낮은 OCR 신뢰도 경고

## 9. 문서 번역

### 공통 원칙

- 원본을 읽기 전용으로 열고 덮어쓰지 않는다.
- 번역 가능한 텍스트와 구조/서식을 분리한다.
- 보호 토큰으로 구조 경계를 유지한다.
- 번역문을 원래 요소에 다시 삽입한다.
- 저장 후 결과 문서를 다시 열어 구조를 검사한다.
- 기본 파일명은 `원본명_번역_대상언어.ext`이며 중복 시 번호를 붙인다.

### DOCX

- 본문, 표, 목록, 텍스트 상자, 머리글/바닥글, 각주/미주를 번역한다.
- 글꼴, 크기, 색상, 강조, 스타일, 그림과 관계를 보존한다.
- 문장 길이 증가 시 줄바꿈을 우선하고 제한적으로 글꼴을 줄인다.

### PPTX

- 슬라이드, 도형, 텍스트 상자, 표, 발표자 노트를 번역한다.
- 위치, 크기, 테마, 이미지, 애니메이션 관계를 보존한다.
- 넘침은 자동 맞춤, 제한적 글꼴 축소, 경고 순으로 처리한다.

### XLSX

- 문자열 셀을 번역하고 수식, 주소, URL, 파일 경로는 보호한다.
- 스타일, 병합, 차트, 조건부 서식, 행과 열 구조를 보존한다.
- 자동 줄바꿈을 적용하며 행/열 크기 자동 변경은 사용자 옵션으로 둔다.
- 시트 이름, 숨김 셀, 메모와 댓글은 선택 항목이다.

### PDF

- 텍스트 PDF와 스캔 PDF를 자동 구분한다.
- 텍스트 PDF는 블록과 좌표를 추출하고 같은 영역에 재배치한다.
- 스캔 PDF는 OCR 후 원문 영역을 복원하고 번역문을 배치한다.
- 동일 글꼴이 없으면 형태가 가까운 대체 글꼴을 사용하고 보고서에 남긴다.
- 원본과 픽셀 단위 동일성을 보장하지 않으며 페이지 구조와 가독성을 우선한다.

### 번역 대상 기본값

- 번역: 본문, 표, 텍스트 상자, 머리글/바닥글, PPT 노트, Word 각주/미주
- 선택: 댓글, 메모, 시트 이름, 숨김 내용, 문서 속성
- 보호: 수식, 셀 주소, URL, 파일 경로, 코드, 변수명, 사용자 보호 용어

## 10. 오류 처리와 복구

모든 작업은 다음 상태를 가진다.

`대기 → 추출 → 번역 → 재배치 → 검증 → 저장 → 완료`

각 단계 종료 시 재개 체크포인트를 로컬 암호화 작업 저장소에 기록한다. 재개에 필요한 본문은 이 저장소 안에서만 암호화하며 개발 로그와 오류 로그에는 넣지 않는다. 네트워크 중단, 로그인 만료, 사용량 제한 또는 앱 종료 후 가능한 지점부터 재개한다. 사용자는 언제든 취소할 수 있다.

일부 요소 실패 시 가능한 부분까지 결과를 만들고 실패한 페이지, 슬라이드, 시트, 셀과 사유를 보고한다. 구조 손상 가능성이 있으면 결과 파일을 저장하지 않고 복구 가능한 임시 상태와 오류 보고서만 남긴다.

## 11. 개인정보와 로컬 기록

- 번역 기록 기본값: 사용, 30일, 로컬 암호화
- 시크릿 번역: 원문, 번역문, 파일 경로 및 미리보기 비저장
- 기록별 삭제, 기간별 자동 삭제, 전체 삭제
- 임시 이미지, 분해 문서 및 OCR 결과는 작업 종료 또는 복구 기간 종료 시 삭제
- 오류 로그에는 원문, 번역문, 토큰, 계정 정보와 전체 경로를 기록하지 않음
- Codex의 영구 스레드 기록에는 번역 원문과 번역문을 저장하지 않음
- 외부 모델 전송 안내를 최초 한 번 표시
- 회사 정책용 기록 금지 설정 제공

## 12. 개발 기록

- PROJECT_LOG.txt: 날짜별 계획, 진행, 완료, 검증
- DECISIONS.txt: 설계 선택, 이유, 제약과 변경
- CHANGELOG.md: 사용자에게 보이는 변경
- docs/superpowers/specs/: 승인된 설계와 구현 계획

구현 단계에서 변경 기록 도구, 커밋 전 검사 및 CI 검사를 추가한다. 기록 누락은 배포 검사 실패 사유가 된다. 번역 내용과 인증 정보는 어떤 개발 기록에도 포함하지 않는다.

## 13. 테스트

### 단위 테스트

- 언어쌍과 설정 검증
- 보호 토큰과 번역 블록 분할
- 연속 단축키 상태기계
- 파일명 충돌과 저장 정책
- 로그 개인정보 제거

### 통합 테스트

- Codex App Server 시작, 로그인 상태, 스트리밍, 만료와 제한
- 번역 세션의 파일 접근 차단, 도구 실행 거부, 프롬프트 인젝션 격리
- OCR 추출부터 번역 재배치까지
- 문서 추출, 번역 삽입, 저장, 재열기
- 작업 취소, 재시도와 복구
- 선택 텍스트 획득 후 기존 클립보드 복원

### 회귀 자료

- 다양한 서식의 DOCX, PPTX, XLSX, PDF
- 텍스트 PDF와 스캔 PDF
- 밝은/어두운 배경, 회전 문자, 표가 있는 이미지
- 주요 언어쌍과 긴 문서

### 배포 관문

- 원본 파일 해시 불변
- 페이지, 슬라이드, 시트, 표, 이미지 개수 검증
- 문서 구조 재열기 성공
- 단축키 등록과 차단 동작
- Windows 10/11, 최신 macOS, Intel/Apple Silicon 빌드
- 개발 및 오류 로그의 민감정보 검사

## 14. 배포와 업데이트

- GitHub Actions 매트릭스에서 Windows, macOS Intel, macOS Apple Silicon을 빌드한다.
- Windows MSI/EXE와 macOS DMG를 생성한다.
- 공개판은 플랫폼별 코드 서명과 macOS 공증 요건을 적용한다.
- 사전 공개판에서 실제 문서와 권한 흐름을 검증한 뒤 안정판으로 승격한다.
- 앱은 GitHub Releases에서 새 버전을 확인한다.
- 변경 내용을 먼저 보여주고 사용자가 동의한 경우에만 설치한다.
- 실패 시 기존 버전으로 되돌릴 수 있는 상태를 보존한다.

## 15. 구현 단계

1. 저장소, 자동 기록, CI 뼈대
2. Tauri 셸, React 화면, 설정 저장
3. Codex 런타임 관리, 로그인, 텍스트 번역
4. 전역 단축키, 팝업, 클립보드 번역
5. 화면 캡처와 OCR, 이미지 결과
6. DOCX와 PPTX
7. XLSX와 PDF
8. 복구, 기록, 개인정보 보호
9. Windows 패키징과 실제 앱 검증
10. macOS 어댑터, 권한, 패키징과 공증
11. 사전 공개판과 안정판

각 단계는 실패하는 테스트 작성, 최소 구현, 검증, 기록 갱신 순으로 진행한다.

## 16. 알려진 제약

- 운영체제는 단축키를 점유한 프로그램의 신원을 항상 공개하지 않는다. 따라서 확정 정보와 가능성 정보를 구분해 표시한다.
- 번역문 길이와 글꼴 차이 때문에 원본 배치를 완벽히 유지할 수 없는 문서가 있다. 자동 조정과 결과 보고서로 처리한다.
- 복잡한 이미지 배경은 원문 제거 흔적이 남을 수 있다.
- Codex의 사용 가능한 모델과 사용량은 사용자의 ChatGPT 요금제 및 당시 서비스 정책을 따른다.
- macOS 화면 캡처와 일부 단축키에는 사용자 권한 승인이 필요하다.
- 공개 배포용 macOS 빌드는 Apple 개발자 인증서와 공증이 필요하다.

## 17. 완료 기준

- 승인된 세 화면에서 모든 핵심 작업을 수행할 수 있다.
- Windows와 macOS에서 로그인, 텍스트 번역, 단축키, 화면 캡처 및 문서 번역이 동작한다.
- 모든 지원 문서가 원본을 보존하고 새 파일을 생성한다.
- 실패 위치와 서식 변경이 사용자에게 보고된다.
- 테스트, 보안, 개인정보, 자동 기록 및 플랫폼 배포 관문을 통과한다.
