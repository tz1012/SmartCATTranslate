SmartCAT Translate 설계 결정 기록
=================================

[D-001] ChatGPT 계정 연결
상태: 승인
결정: MCP나 비공식 ChatGPT 세션 자동화가 아니라 공식 Codex App Server를 사용한다.
이유: 공식 브라우저 인증, 구독 기반 Codex 사용, 토큰 갱신과 계정 상태 처리를 활용할 수 있다.

[D-002] 데스크톱 기술 기반
상태: 승인
결정: Tauri 2 + React + TypeScript + Rust를 사용한다.
이유: Windows와 macOS를 하나의 저장소에서 지원하고 Electron보다 가벼운 앱을 만들기 위함이다.

[D-003] 플랫폼 빌드
상태: 승인
결정: GitHub Actions의 Windows 및 macOS 실행 환경에서 플랫폼별 설치 파일을 만든다.
주의: macOS 공개 배포에는 Apple 코드 서명과 공증이 필요하다.

[D-004] Codex 실행 환경
상태: 승인
결정: 기존 공식 Codex 설치를 우선 탐색하고, 없으면 앱 전용 폴더에 검증된 공식 Codex를 설치한다.
이유: 비기술 사용자도 별도 명령 입력 없이 로그인하고 사용할 수 있게 한다.

[D-005] 전역 단축키
상태: 승인
결정: 일반 조합과 Ctrl+C, C 같은 연속 입력을 지원한다. 충돌 시 등록 차단, 원인 안내, 대체 조합 추천을 기본으로 하고 경고 후 강제 등록을 허용한다.
제약: 운영체제가 점유 프로그램을 공개하지 않는 경우에는 실행 중인 앱과 알려진 단축키 자료를 이용해 충돌 가능성을 표시한다.

[D-006] 번역 대상
상태: 승인
결정: 텍스트, 이미지, 화면 캡처, DOCX, PPTX, XLSX, PDF를 지원한다.

[D-007] 문서 보존
상태: 승인
결정: 원본과 같은 형식의 새 번역 파일을 만들며 원본은 절대 덮어쓰지 않는다. 저장 후 문서 구조를 다시 검사한다.

[D-008] 화면 구성
상태: 승인
결정: 전체 번역 창, 작은 빠른 번역 팝업, 화면 캡처 결과 창을 제공한다.

[D-009] 번역 설정
상태: 승인
결정: 빠른/균형/정밀 품질, 언어 자동 감지, 언어쌍 즐겨찾기, 단축키별 언어쌍, 문체와 분야, 용어집을 제공한다.

[D-010] 개인정보와 기록
상태: 승인
결정: 번역 기록은 기본 30일간 로컬 암호화 저장하고 시크릿 모드를 제공한다. 토큰, 원문, 번역문은 개발 로그에 기록하지 않는다.

[D-011] 앱 업데이트
상태: 승인
결정: GitHub Releases에서 새 버전을 확인하고 변경 내용을 먼저 표시한 뒤 사용자의 동의를 받아 설치한다.
이유: 예기치 않은 자동 변경을 방지하면서도 비기술 사용자가 쉽게 업데이트할 수 있게 한다.

[D-012] 오류 복구
상태: 승인
결정: 추출, 번역, 재배치, 검증, 저장 단계별 상태를 보존하고 네트워크 중단, 로그인 만료, 사용량 제한, 앱 비정상 종료에서 복구 가능한 작업을 재개한다.

[D-013] 품질 검증
상태: 승인
결정: 단위, 통합, 실제 앱 동작 테스트와 원본 불변성, 문서 구조, 서식, OCR 좌표, 개인정보 비기록 검사를 통과해야 배포한다.

[D-014] 배포
상태: 승인
결정: GitHub Actions에서 Windows와 macOS 설치 파일을 만들고 사전 공개판 검증 후 안정판을 배포한다. 공개판은 플랫폼별 서명과 공증 요건을 적용한다.

[D-015] 구현 계획 분할
상태: 확정
결정: 전체 구현을 기반·Codex 텍스트, 단축키·팝업, 이미지·화면 캡처, 문서 번역, 기록·복구·배포의 다섯 독립 계획으로 나누고 이 순서로 통합한다.
이유: 각 계획이 검토 가능한 실행 결과와 자체 테스트 관문을 갖게 하기 위함이다.

[D-016] Codex 번역 내용 격리
상태: 확정
결정: 번역 내용이 없는 기반 스레드만 로컬에 만들고, 실제 원문과 번역문은 매 요청마다 생성하는 메모리 전용 임시 포크에서만 처리한다. 제한된 읽기 전용 샌드박스, 승인 금지, 빈 MCP 구성을 적용하고 도구 실행 요청이 발생하면 번역을 중단한다.
이유: ChatGPT 계정 인증을 이용하면서도 원문과 번역문이 Codex 영구 스레드 기록이나 외부 도구로 흘러가는 것을 방지하기 위함이다.

[D-018] ChatGPT 브라우저 로그인 주소 경계
상태: 확정
결정: 공식 Codex App Server가 호스팅 로그인 성공 화면을 사용하는 ChatGPT 브라우저 흐름에서 반환한 주소만 운영체제 브라우저로 넘긴다. HTTPS `chatgpt.com` 또는 그 DNS 하위 도메인만 허용하고, URL 사용자 정보, 비표준 포트, 유사 도메인, IP 주소와 다른 스킴은 거부한다.
이유: 공식 문서의 브라우저 흐름은 `chatgpt.com` 인증 주소를 반환하므로 이보다 넓은 외부 주소 열기 권한이 필요하지 않다. 인증 주소와 로그인 식별자는 화면 이벤트, 오류와 기록에 포함하지 않는다.
취소 규칙: 로그인 취소 요청이 성공한 뒤에만 로컬 대기 상태를 지운다. 브라우저 열기와 자동 취소가 모두 실패하면 대기 상태를 유지하고 사용자가 취소를 다시 시도할 수 있게 한다.

[D-019] Codex App Server 운영 부트스트랩과 HTTPS 다운로드
상태: 확정
결정: Tauri 설정 단계는 화면을 막지 않는 백그라운드 작업으로 공식 시스템 Codex 탐색, 검증된 앱 전용 런타임 설치, `codex app-server --listen stdio://` 실행, 공식 `initialize`/`initialized` 핸드셰이크, JSONL 전송 계층과 계정 서비스 설치를 순서대로 수행한다. 실행은 셸을 통하지 않고 고정 인수만 사용하며 앱 데이터 아래의 비어 있는 임시 작업 디렉터리에서 수행한다.
다운로드 경계: `reqwest` 0.13을 기본 기능 없이 `native-tls-no-alpn`으로 사용한다. 자동 리디렉션을 끄고 고정된 OpenAI/Codex GitHub 릴리스 주소에서 정확히 한 번 `release-assets.githubusercontent.com`으로 이동하는 HTTPS 요청만 허용한다. 연결은 15초, 전체 요청은 180초로 제한하고 매니페스트 크기·SHA-256·아카이브 구조 검증을 그대로 적용한다.
이유: Windows와 macOS의 운영체제 신뢰 저장소를 재사용하면서 추가 TLS 공급망을 최소화하고, 비기술 사용자가 별도 CLI 설치 없이도 검증된 Codex 계정 연결을 사용할 수 있게 한다.
수명주기: 앱 상태가 계정 서비스와 실제 전송 계층을 함께 소유한다. 앱 종료가 시작되면 늦게 끝난 부트스트랩 설치를 거부하고, 프로세스 종료를 기다린 뒤 임시 작업 디렉터리를 정리한다. 준비 실패는 고정된 사용자 상태로만 닫히며 경로, 원시 JSON, 인증 주소, 로그인 식별자나 원격 오류 문구를 기록하지 않는다.

[D-020] 구조화 번역 스트림과 실패 폐쇄 수명주기
상태: 확정
결정: 번역 요청은 내용이 없는 단일 기반 스레드에서 메모리 전용 임시 스레드를 포크하고, 원문은 그 임시 스레드의 `turn/start`에만 전달한다. 출력은 `translation` 문자열 하나만 허용하는 구조화 스키마로 제한하며, 스트림 델타의 JSON 문자열 값만 화면에 보내고 최종 에이전트 메시지를 권위 있는 결과로 검증해 중복을 제거한다.
보안 경계: 승인 정책은 항상 `never`, 샌드박스는 앱 소유의 비어 있는 작업공간만 읽을 수 있는 제한된 `readOnly`, App Server MCP 구성은 빈 맵으로 고정한다. 명령·프로세스·파일 변경·MCP·웹·동적 도구·승인·협업·하위 에이전트 및 모든 서버 요청은 스레드와 턴 범위가 일치하면 실패 폐쇄로 중단하고 임시 구독을 해제한다.
수명주기: 이벤트 구독을 요청 전 시작해 응답보다 먼저 온 델타를 보존하고, 모든 수락 이벤트를 임시 스레드 ID와 턴 ID로 함께 제한한다. 크기·시간·취소·프로세스 종료·수신 지연·잘못된 구조·동시 작업을 제한하며 창 종료는 해당 창 작업만, 앱 종료는 모든 작업과 기반 스레드를 순서대로 정리한다. 정리 요청마다 독립 제한시간을 두고 기반 스레드 삭제 실패는 재시도할 수 있게 한다.
기록 경계: 원문·번역문·원시 App Server 페이로드·인증 정보·전체 로컬 경로는 로그와 오류에 포함하지 않는다. 번역 본문은 요청 창의 Tauri 이벤트 페이로드에만 존재한다.

[D-021] Codex 번역 런타임의 완전 격리
상태: 확정
결정: 번역용 Codex App Server는 앱 데이터 아래의 전용 `CODEX_HOME`, 원자적으로 작성한 완전한 제한 구성, 앱 소유의 표준 빈 작업공간에서만 실행한다. 사용자 Codex 구성은 상속하지 않으며, 파일 저장 방식이면 유효한 `auth.json` 하나만 전용 홈으로 제한 복사하고 파일 자격 증명이 없으면 운영체제 키링을 사용한다.
선실행 차단: 승인·셸·웹·이미지·앱·MCP·기술·훅·에이전트·기억·원격 플러그인·분석·기록 기능은 구성에서 비활성화한다. 기반 스레드는 지시 출처가 존재하지 않음을 응답으로 확인하고, 번역 중에는 정확한 수명주기·텍스트 이벤트 허용 목록 외의 같은 작업 이벤트를 모두 중단한다.
무결성 경계: 전용 홈과 작업공간의 심볼릭 링크·정션·재분석 지점 조상을 거부하고, 작업공간과 앱 데이터 루트의 파일 시스템 식별자를 요청마다 다시 확인한다. 창 소유권 tombstone은 작업 예약과 원자적으로 결합하며, 취소 중 턴 식별자를 끝내 얻지 못하면 해당 런타임을 오염 상태로 표시하고 종료한다.
이유: 사후 이벤트 거부만으로는 도구가 실행되기 전의 보안 경계를 보장할 수 없고, 사용자 구성·지시 파일·경로 교체·창 종료 경합이 원문 처리 권한을 넓히지 못하게 해야 하기 때문이다.

[D-022] Codex App Server 운영체제 격리와 안정판 호환성 차단
상태: 구현 완료·Windows 안정판 호환성 차단 확인
결정: Windows에서는 별도 AppContainer 프로필, 앱 전용 패키지 저장소, 명시적 파일 ACL과 `internetClient` 기능만으로 Codex App Server를 실행한다. macOS에서는 고정 Codex의 Seatbelt 기반 `sandbox --permission-profile` 경로와 최소 실행 파일·전용 홈·빈 작업공간 권한만 사용한다. 그 밖의 플랫폼 또는 격리 설정 실패에서는 실행하지 않으며 격리 없는 폴백을 금지한다.
검증 경계: Windows AppContainer 보조 프로세스가 허용 폴더에는 쓸 수 있고 바로 옆 비밀 파일은 읽지 못함을 실제 프로세스로 확인했다. 생성 구성은 고정 Codex 0.144.4 스키마와 실제 0.144.4 `features list` 파서에서 통과한다.
열린 차단: 같은 AppContainer에서 고정 Codex 0.144.4 App Server는 허용된 전용 `CODEX_HOME`의 절대 경로와 현재 디렉터리 `.` 모두를 `canonicalize`할 때 Windows 오류 5로 종료한다. 부모 경로 ACL을 넓히거나 격리 없이 실행하면 외부 파일 읽기 불변식을 깨므로 채택하지 않는다.
안전한 해소 조건: (1) AppContainer에서 전용 홈을 정상 처리하는 안정판 Codex로 고정 버전을 올리고 공급망 매니페스트를 다시 승인하거나, (2) 앱이 직접 소유하는 별도 최소 권한 브로커/가상화 경계를 설계·검증하거나, (3) 사용자 파일이 없는 별도 운영체제 계정/VM 경계로 실행해야 한다. 그 전까지 Windows 번역 백엔드는 초기화 실패로 닫힌다.
네트워크 경계: AppContainer의 운영체제 기능은 임의 도메인까지 구분하지 못한다. App Server의 공식 계정·모델 HTTPS 통신을 위해 `internetClient`가 필요하고, 모든 번역 턴에는 안정 프로토콜이 지원하는 `readOnly` 및 `networkAccess: false`를 함께 적용한다.

[D-023] SmartCAT 전용 Codex 0.144.4 하류 런타임
상태: 확정 — D-017, D-019, D-022의 운영 런타임 선택·다운로드·AppContainer 부분을 대체함
결정: 번역과 계정 연결에는 시스템 Codex나 공개 공식 바이너리를 사용하지 않고, OpenAI Codex `rust-v0.144.4`의 정확한 커밋 `8c68d4c87dc54d38861f5114e920c3de2efa5876`에서 감사 가능한 최소 패치 `smartcat-1`을 적용해 각 설치 대상에서 직접 빌드한 sidecar만 사용한다. 소스 보관 파일, 변경 전 파일과 패치의 SHA-256을 `runtime-patches/codex-0.144.4-smartcat/pin.json`에 고정하고 변화 시 빌드를 중단한다.
컴파일 불변식: 최종 모델 요청 조립 경계에서 모든 구성·모델·공급자·기능 상태와 관계없이 도구 선언을 빈 목록으로 강제하고 병렬 도구 호출을 끈다. 사용자·프로젝트 지시문 탐색 함수는 원문 파일을 읽지 않고 항상 없음으로 끝나며 `thread/start`의 `instructionSources`는 빈 배열이어야 한다. 이 두 경계와 App Server 동작은 패치가 적용된 업스트림 소스 안의 시험으로 검증한다.
실행 증명: 패치 전용 안정 메서드 `smartcat/attestation`은 정확한 업스트림 커밋, 패치 버전, `toolCount=0`, `instructionDiscovery=false`를 반환한다. 앱은 `initialize`를 완료한 바로 그 stdio 세션에서 이 값을 확인하며, 실행 전에 설치기에 포함된 바이너리의 크기와 SHA-256을 빌드 생성 매니페스트와 대조한다. stock 또는 변조된 Codex, 매니페스트 없는 sidecar, 다른 세션은 거부하며 시스템·다운로드 폴백은 없다.
배포 경계: Windows x86_64, macOS x86_64, macOS arm64는 각 대상의 명시적 GitHub Actions 릴리스 작업에서 고정 소스·패치 시험, `cargo --locked` 빌드, 체크섬·provenance·SBOM 생성 후 Tauri `externalBin`으로 설치기에 포함한다. 공개 배포 서명·공증은 D-003과 D-014의 플랫폼 자격 증명 경계를 그대로 따른다. 커밋·보관 파일·패치·잠금 파일은 재현 가능한 입력으로 고정하지만 서로 다른 호스트의 바이트 동일성은 별도 증명 없이는 주장하지 않는다.
보존 경계: 앱 전용 `CODEX_HOME`, 최소 ChatGPT 자격 증명 가져오기, 사용자 환경 제거, 빈 앱 소유 작업공간, `approvalPolicy=never`, 턴의 `readOnly`와 `networkAccess=false`, 서버 요청 및 허용 목록 밖 알림의 실패 폐쇄, 중단 실패 오염과 창 tombstone 규칙은 계속 적용한다. 이전 AppContainer와 Seatbelt 실행 구현은 제품 소스에서 제거하며 격리 없는 stock Codex 경로로 우회하지 않는다.

[D-024] 릴리스 SBOM과 산출물 provenance 완전성
상태: 확정
결정: 명시적 3대상 릴리스 작업은 고정된 `cargo-cyclonedx`로 하류 Codex와 Tauri Rust의 각 잠금 의존성 그래프를 만들고, 고정된 Syft로 저장소 작업공간의 프런트엔드·소스 의존성을 별도 수집한다. sidecar와 Tauri bundle 아래의 모든 플랫폼 설치 파일은 실제 바이트 SHA-256과 CycloneDX 산출물 목록에 함께 포함한다.
실패 폐쇄: Cargo 잠금 파일이 SBOM 생성 중 바뀌거나, 어떤 SBOM이 비어 있거나 구성 요소가 2개 미만이거나, Rust SBOM에 실제 의존 관계가 없거나, checksum 생성 뒤 sidecar·설치 파일이 바뀌면 attestation과 업로드를 시작하지 않는다. GitHub provenance는 검증된 checksum 파일을 입력으로 사용해 sidecar와 모든 설치 파일을 한 번에 대상으로 삼고, 업로드는 이 단계의 성공 뒤에만 실행한다.
일반 CI: 네트워크 다운로드나 하류 Codex 대형 빌드 없이 공급망 스크립트와 릴리스 순서의 계약 시험만 Windows와 macOS에서 항상 실행한다. 실제 3대상 빌드·SBOM·설치기·attestation은 수동 릴리스 작업에 한정한다.

[D-025] 번역 설정 저장과 계정 모델 선택 경계
상태: 확정
결정: 비밀정보가 아닌 앱 설정은 스키마 버전 1의 앱 전용 JSON 파일로 저장한다. 같은 디렉터리의 임시 파일을 완전히 기록하고 파일 동기화를 마친 뒤 원자 교체하며, 제품 설정 경로에는 종료 시 별도 저장을 수행하는 플러그인 저장소를 사용하지 않는다. 저장 작업은 직렬화하고 앱 종료는 진행 중인 저장을 기다리며, 내구 저장이 실패하면 메모리의 권위 있는 설정을 바꾸지 않는다. 기본값은 원문 자동 감지, 대상 한국어, 균형 품질, 자연스러운 문체, 시스템 테마와 한국어 화면이며 보존 기간은 30일로 검증하되 번역 기록 저장 자체는 후속 암호화 기록 단계에서 활성화한다.
검증 경계: 기본 프로필은 항상 존재해야 하고 프로필·용어집·보호 용어·언어 태그·모델 식별자·보존 기간은 Rust에서 저장 전에 검증한다. 보호 용어와 용어집 합계는 번역 프롬프트의 최대 1,000개·64 KiB 경계 안에 있어야 하며 설정 문서, 모델 목록 페이지·필드·커서·식별자도 제한한다. 용어집 식별자와 정규화된 원문 키는 중복될 수 없다. 같은 언어쌍은 번역 모드를 자동 변경하지 않고 문장 개선을 제안하며 실제 번역 명령도 일반 번역 요청을 거부하고 명시적인 문장 개선 경로를 요구한다.
모델 경계: 모델 목록은 초기화된 동일 Codex App Server 세션의 `model/list`가 현재 계정에 반환한 항목만 표시하며 숨김 모델이나 앱이 임의로 만든 모델은 추가하지 않는다. 저장한 특정 모델은 권위 있는 목록에서 사라진 것이 확인된 경우 실제 작업에서 자동 선택으로 해석한다. 목록 조회 실패 때 화면은 저장한 선택을 보존하고, 번역 작업은 특정 모델을 선택한 경우 실패 폐쇄하되 자동 선택인 경우에만 모델 필드를 생략해 프로토콜 기본 모델로 진행한다. 로그아웃과 취소는 일시적인 목록 오류와 구분해 번역을 중단한다. 해석한 특정 모델은 `turn/start`의 모델에 실제로 적용하고 자동 선택은 모델 필드를 보내지 않는다.
번역 전 확인 경계: 설정 읽기, 계정 확인과 `model/list`는 원문을 전달하기 전에 번역 작업 예약을 먼저 만든 뒤 그 작업의 창·앱 취소 신호와 동일한 전체 제한시간 안에서만 실행한다. 각 확인에는 더 짧은 상한도 적용하며 취소 또는 제한시간 만료 시 대기 중 전송 요청을 제거한다. 특정 모델은 권위 있는 확인이 불가능하면 실패 폐쇄하고, 자동 선택만 프로토콜 기본 모델을 뜻하는 모델 필드 생략으로 전환한다. 확인에 쓴 시간은 원문을 포함하는 턴의 남은 제한시간에서 차감한다.
화면 경계: 모델 목록 조회 실패는 저장한 선택을 지우지 않는다. 계정 상태 변경 이벤트마다 목록을 다시 조회하고 한국어·영어 재시도를 제공하며, 늦게 도착한 이전 조회 응답과 화면 해제 뒤 응답은 세대 번호로 폐기한다. 저장 응답에도 별도 세대 번호를 적용해 응답 대기 중 발생한 새 편집을 오래된 응답이 덮어쓰지 못하게 하고, UUID 폴백은 암호학적 난수로 RFC 4122 버전 4와 variant 비트를 강제한다.
이유: 설정 손상과 계정별 모델 차이를 실패 폐쇄로 처리하면서 사용자의 명시적 선택과 저장 중 새 편집을 조용히 덮어쓰지 않기 위함이다.

[D-026] 텍스트 작업 화면 요청·저장·이벤트 일관성
상태: 확정
결정: 텍스트 번역 요청은 저장한 분야와 현재 언어쌍에 맞는 원문·대상 용어 매핑을 안정된 직렬화 계약으로 전달한다. 보호 전용 용어는 기존 보호 용어 목록에만 합치며, 원문·분야·용어집 전체를 번역을 위한 비신뢰 데이터로 취급하고 도구·명령·파일 접근과 그 밖의 동작을 요청하거나 수행하지 못하게 한다. 각 용어, 항목 수와 보호 용어를 합한 전체 바이트 수를 Rust 경계에서 제한한다.
화면 경계: 번역 이벤트 구독이 성공한 뒤에만 새 작업을 시작한다. 진행 중에는 원문·언어쌍·프로필 변경을 막고, 원문 입력은 초점을 유지하는 읽기 전용 상태로 전환해 Escape 취소를 계속 받을 수 있게 한다. 번역 또는 취소 정리가 진행되는 동안 앱의 설정 탭은 한국어·영어 이유를 알리며 비활성화하고 번역 화면은 해제하지 않는다. 완료 뒤 원문·언어쌍을 바꾸면 감지 언어와 결과를 함께 지운다. 로그아웃 뒤에도 이미 시작한 작업의 취소는 허용하며, 취소가 거부되거나 실패하면 해당 작업 정리가 확인될 때까지 새 작업과 편집을 막고 고정된 한국어·영어 오류와 정리 재시도를 제공한다. 완료·오류·취소·화면 해제 시 활동 상태를 해제하고, 화면 해제와 창 종료는 남은 구독과 작업을 정리하며 늦거나 다른 작업의 이벤트를 적용하지 않는다.
저장 경계: 번역문 저장은 브라우저 다운로드가 아니라 Tauri Rust가 여는 운영체제 저장 대화상자와 사용자가 고른 경로만 사용한다. 대화상자 제목과 파일 유형은 Rust의 한국어·영어 허용 목록에서만 선택하며 임의 문자열은 대화상자를 열기 전에 거부한다. 대화상자 취소는 정상 결과이고, 선택·쓰기 실패는 번역 내용과 경로를 포함하지 않는 단일 고정 오류로 닫힌다. 번역 내용과 임의 언어 값은 기록·진단·앱 기록 저장소에 남기지 않는다.
화면 구성: 번역과 설정을 한국어·영어 접근 가능한 탭으로 제공하고 저장된 테마를 앱 루트에 적용한다. 비활성 후속 작업 탭도 탭과 패널 관계를 명시한다. Tauri 콘텐츠 보안 정책은 자체 자산, IPC, 개발 서버에 필요한 연결만 허용하고 객체·프레임·폼 전송을 금지한다.
검증 경계: Playwright 1.62.1 exact 버전으로 실제 프런트엔드 요청 인자, 스트림, 복사와 데스크톱·모바일 재배치를 검사한다. CI 브라우저 캐시는 운영체제·Playwright exact 버전·잠금 파일에 묶고 프로젝트의 드라이브 위치에 의존하지 않는다.

[D-027] 전역 단축키 충돌 판정과 근거 카탈로그
상태: 확정
결정: 단축키 충돌은 (1) 실제 운영체제 등록 시험, (2) 등록할 수 없는 운영체제 예약 조합, (3) 실행 중인 프로그램의 프로세스 이름과 공식 단축키 카탈로그 일치 결과를 합성한다. 등록 시험 실패와 운영체제 예약 조합은 `확정`, 실행 중 앱의 알려진 기능과 일치하는 경우는 `가능성`으로 구분한다. 등록 시험이 실패했지만 소유자를 확인할 수 없으면 프로그램명을 추측하지 않고 `다른 프로그램이 사용 중일 수 있습니다.`라고만 표시한다. 카탈로그에 없다는 사실은 충돌이 없다는 완전한 증명이 아니며 실제 등록 시험이 우선한다.
강제 규칙: 충돌이 없을 때만 기본 등록을 허용한다. 앱 카탈로그 가능성 또는 소유자 미상 점유는 사용자가 경고를 확인한 경우에만 강제할 수 있으나, 운영체제 예약 조합은 강제할 수 없다. 강제는 후속 플랫폼 관찰기의 의도적 대체 경로를 허용한다는 뜻이며 다른 앱 동작이 사라지거나 모든 환경에서 감지된다고 보장하지 않는다.
추천 규칙: 같은 키에 수정 키를 더한 후보를 먼저, 기능 키 후보를 다음으로 만들고 원래 분석기의 운영체제 예약, 실제 등록 시험과 실행 중 앱 검사를 모두 다시 통과한 앞의 3개만 고정 순서로 제시한다.
카탈로그 경계: 스키마 버전 1, 카탈로그 버전, 256KiB, 최대 1,024행, 필드·프로세스 이름 제한, 중복 금지, HTTPS 공식 1차 출처 허용 목록, 검증일 18개월 제한과 SHA-256을 적용한다. 운영 빌드는 검토된 JSON 바이트를 컴파일 시 실행 파일에 포함하므로 런타임 경로, 심볼릭 링크, 정션이나 외부 파일 교체를 따라가지 않는다. 해시·스키마·버전·출처·검증일이 맞지 않으면 카탈로그를 사용하지 않는다.
개인정보 경계: 실행 중 프로그램에서는 제한된 실행 파일/프로세스 이름만 받으며 전체 경로, 창 제목과 키 입력은 수집·일치·보고하지 않는다. 보고서의 프로그램명·기능·URL은 해시로 고정된 카탈로그 값만 사용한다.
공식 출처(2026-08-30 확인): Windows `RegisterHotKey` https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey, macOS 단축키 https://support.apple.com/en-us/102650, Chrome https://support.google.com/chrome/answer/157179, Edge https://support.microsoft.com/en-us/edge/keyboard-shortcuts-in-microsoft-edge, VS Code https://code.visualstudio.com/docs/reference/default-keybindings, DeepL https://support.deepl.com/hc/en-us/articles/360020613059-Use-DeepL-shortcuts-for-desktop-apps, Word https://support.microsoft.com/en-us/accessibility/word/keyboard-shortcuts-in-word, PowerPoint https://support.microsoft.com/en-us/office/keyboard-shortcuts-for-working-with-shapes-text-boxes-and-wordart, Excel https://support.microsoft.com/en-us/accessibility/excel/use-a-screen-reader-to-sort-or-filter-a-table-in-excel.

[D-028] 전역 단축키 충돌 판정의 연속 입력·플랫폼 관찰 능력 경계
상태: 확정 — D-027의 연속 입력, 강제 규칙, 앱 식별, 추천과 PowerPoint 출처를 구체화함
결정: 연속 단축키는 전체 문자열뿐 아니라 모든 단계가 기존 프로그램으로 그대로 전달된다는 전제에서 각 단계를 운영체제 예약과 실행 중 앱 카탈로그에 대조한다. 두 연속 입력은 접두사·접미사가 겹쳐 한 입력이 다른 입력을 시작하거나 완성할 수 있는 경우도 충돌로 본다. Windows에서는 Meta/Win 수정 키가 포함된 어느 단계든 광범위한 운영체제 예약 조합으로 분류해 강제할 수 없게 한다.
등록 시험 계약: 결과를 `Available`, 관찰기 사용 가능 여부를 포함한 `Occupied`와 `UnsupportedSequence`, `PermissionDenied`, `Invalid`, `OsReserved`, 상세를 담지 않는 `BackendError`로 구분한다. 점유 또는 직접 등록 불가 연속 입력은 후속 플랫폼 관찰기가 실제 사용 가능하다고 보고한 경우에만 강제할 수 있다. 실행 중 앱 카탈로그만 충돌하고 직접 등록은 가능한 경우에는 경고 확인 후 강제할 수 있다. 권한 거부, 잘못된 조합, 운영체제 예약과 백엔드 오류는 강제할 수 없다. Task 3은 이 포트와 가짜 구현까지만 제공하며 네이티브 등록기·관찰기는 Task 4에서 구현한다.
앱 식별 경계: 실행 파일의 정제된 basename과 선택적인 macOS bundle identifier만 사용한다. 경로 구분자, 드라이브 접두사, 제어 문자와 제한 초과 값은 거부하고 창 제목·키 입력·전체 경로는 받거나 기록하지 않는다. VS Code는 `Code`, `Electron` 실행 이름 변형과 `com.microsoft.VSCode` bundle identifier를 공식 카탈로그 행에 함께 둔다.
추천 규칙: 모든 후보를 같은 전체 충돌 분석기에 다시 넣고 충돌 없음으로 판정된 후보만 결정적 순서로 최대 3개 제시한다. 일반적으로 자주 쓰이는 무수정 기능 키는 제안하지 않고 Ctrl+Alt+Shift가 포함된 F13~F24 같은 더 안전한 후보를 우선한다. 실행 중 VS Code의 F8/F9와 Word의 Ctrl+Shift+L 등 카탈로그 단축키는 추천하지 않는다.
카탈로그 경계: 카탈로그의 trigger 문자열은 파싱한 정규형과 원문이 정확히 같아야 한다. 스키마 버전 1, 카탈로그 버전 `2026.08.30.2`, 제한된 process/bundle 식별자와 검토된 SHA-256을 사용한다. 카탈로그는 알려진 공식 조합의 보수적 스냅샷일 뿐 전역 충돌의 완전한 목록이라고 주장하지 않으며, 오래되거나 검증에 실패하면 사용하지 않는다.
공식 출처 변경(2026-08-30 확인): PowerPoint 현재 접근성 단축키 문서 https://support.microsoft.com/en-us/accessibility/powerpoint/use-keyboard-shortcuts-to-create-powerpoint-presentations. 나머지 출처는 D-027과 동일하다.

[D-029] 연속 단축키 충돌 방향과 실제 입력 가능한 대체키
상태: 확정 — D-028의 연속 입력 겹침, 정상 관찰, 앱 식별과 대체키 규칙을 대체함
충돌 방향: 사용자가 지정한 후보 안에 실행 중 앱의 카탈로그 단축키 전체가 연속 부분열로 포함될 때만 앱 충돌로 기본 차단한다. 후보 전체가 더 긴 카탈로그 연속 단축키의 엄격한 시작 접두사이면 입력이 지연될 수 있다는 `Advisory` 원인만 표시하고 기본 저장은 허용한다. 후보 앞에 무관한 단계가 있고 끝부분만 카탈로그 접두사와 같거나 두 연속 입력이 임의의 한 단계만 공유하는 경우에는 충돌로 분류하지 않는다. 운영체제의 단일 예약 조합이 후보 어느 단계에 포함되는 경우와 Windows Meta/Win 광역 규칙은 계속 확정 차단한다.
관찰 상태: `AvailableViaObserver`는 연속 입력을 비소비 관찰기로 정상 지원하고 필요한 권한이 이미 준비된 상태이므로 충돌이 아니며 기본 저장을 허용한다. `UnsupportedSequence` 또는 `Occupied`에서 관찰기 폴백을 사용하는 경우에만 경고 확인이 필요하고, 관찰기가 실제 사용 가능하지 않으면 강제할 수 없다.
등록 시험 복구 계약: `probe_and_restore`는 영구 상태를 남기지 않는 시험이다. 직접 등록 성공을 확인하면 반환 전에 즉시 등록 해제하여 호출 전 상태를 복구해야 하고, 원시 백엔드 상세는 반환하지 않는다. Task 4 네이티브 어댑터는 이 사후조건을 구현하고 계약 시험을 통과해야 한다.
추천 입력 정책: 물리 키보드에서 일반적으로 직접 입력 가능한 A~Z와 0~9만 대체 후보 키로 사용한다. 원래 후보가 이 범위이면 같은 키에 수정 키를 추가한 조합을 먼저 검사하고, 부족하면 Ctrl+Alt+Shift와 고정 순서의 문자·숫자 조합을 검사한다. F13~F24와 희소 물리 키는 추천하지 않으며 모든 후보는 동일한 전체 분석기를 다시 통과한다.
앱 식별 권위: bundle identifier가 있으면 해당 값을 권위 있게 비교하며 불일치 후 실행 파일 basename으로 폴백하지 않는다. bundle identifier가 없을 때만 정제된 basename을 사용한다. VS Code 카탈로그는 Windows `Code.exe`/`Code`, macOS `Visual Studio Code`/`Code`와 `com.microsoft.VSCode`만 사용하고 일반 `Electron` 별칭은 사용하지 않는다. 카탈로그 버전은 `2026.08.30.3`이며 기존 스키마·해시·freshness 경계는 유지한다.

[D-030] macOS DeepL 앱 식별과 개선 단축키 근거
상태: 확정 — D-029의 bundle identifier 권위 규칙에 필요한 DeepL 식별 정보를 보완함
앱 식별: DeepL 공식 macOS 페이지가 제공한 `https://www.deepl.com/en/macos/download/DeepL.dmg`의 `DeepL.app/Contents/Info.plist`에서 `CFBundleIdentifier`가 `com.linguee.DeepLCopyTranslator`임을 2026-08-30에 확인했다. 확인한 공식 DMG의 앱 버전은 `26.6.14916780`, SHA-256은 `e5507b544654795fc06d6a73090b3c15421913f6acba0bcbf81f6066bb50917c`이다. 모바일 앱 식별자나 추측한 값을 데스크톱 행에 사용하지 않는다.
단축키 근거: 현재 DeepL 공식 데스크톱 단축키 문서 `https://support.deepl.com/hc/en-us/articles/360020613059-Use-DeepL-shortcuts-for-desktop-apps`에서 Windows 선택 번역은 Ctrl을 유지한 채 C를 두 번, macOS 선택 번역은 Command를 유지한 채 C를 두 번, macOS 선택한 텍스트 개선은 Ctrl+Command+C임을 2026-08-30에 확인했다. 내부 정규형은 각각 `Ctrl+C, Ctrl+C`, `Meta+C, Meta+C`와 `Ctrl+Meta+C`이다. 두 번째 C 전에 수정 키를 놓는 `Ctrl+C, C`와 `Meta+C, C`는 다른 입력이므로 DeepL 충돌로 간주하지 않는다.
카탈로그 결정: 두 macOS DeepL 행 모두 권위 있는 bundle identifier를 포함한다. 카탈로그 버전을 `2026.08.30.5`로 올리고 검토된 SHA-256 `5d14b12e9bb1aeb7bf665aaec1a0868a3173e482ada0089e897b2d5e975b75e4`로 묶는다. 기존 크기·스키마·출처·freshness 제한은 유지한다.

[D-031] 운영체제 전역 키 관찰과 포그라운드 앱 개인정보 경계
상태: 확정
결정: Windows의 단일 조합 충돌 시험은 스레드 범위 `RegisterHotKey`로 실제 등록하고 성공한 정확한 식별자를 반환 전에 즉시 `UnregisterHotKey`한다. 연속 입력은 직접 등록 가능한 것으로 가장하지 않고 저수준 비소비 관찰기의 실제 사용 가능 여부를 별도 구조화 상태로 반환한다. Windows 키 입력은 전용 메시지 루프의 `WH_KEYBOARD_LL` 후크로 관찰하고 언제나 `CallNextHookEx`로 원래 프로그램에 전달한다.
macOS 경계: 접근성 권한이 이미 허용된 경우에만 `CGEventTapCreate`의 listen-only 옵션으로 키 down/up을 관찰한다. 권한이 없거나 이벤트 탭을 만들 수 없으면 `AccessibilityPermissionRequired`로 실패 폐쇄하며 입력을 변경하는 폴백을 사용하지 않는다. Intel과 Apple Silicon 각각의 GitHub macOS 실행 환경에서 네이티브 코드를 컴파일·시험한다.
성능·수명주기: 운영체제 콜백은 고정 크기 채널에 `try_send`만 수행하고 UI나 연속 입력 소비자가 늦어도 키 입력 스레드를 기다리게 하지 않는다. 플랫폼별 관찰기는 프로세스당 하나만 허용하며 종료 시 후크/이벤트 탭과 메시지 루프를 정리한다. 중복 시작은 타입이 있는 오류로 거부하고 정상 종료 뒤 재시작할 수 있어야 한다.
개인정보 경계: 포그라운드 앱 확인 중 운영체제 API가 반환한 경로는 메모리에서 즉시 basename으로 축소한다. 공개 결과에는 정제된 실행 파일 basename과 macOS bundle identifier만 포함하며 전체 경로, 창 제목, 키 값, 선택 텍스트와 프로세스 식별자를 로그·오류·디버그 출력에 넣지 않는다.
종료 오류 경계: 플랫폼 관찰기의 종료 호출이 구조화된 오류를 반환해도 컨트롤러는 상태기계 worker 회수를 건너뛰지 않는다. 플랫폼 오류를 보존한 채 worker를 join하고 모든 소유 핸들을 제거하여 재시도나 객체 해제 시 네이티브 스레드를 방치하지 않는다.

[D-032] 네이티브 단축키 관찰기의 복구·건강 상태 경계
상태: 확정
등록 복구: Windows 직접 등록 시험은 전용 짧은 수명 스레드가 등록을 소유하고 RAII lease가 같은 식별자의 해제를 제한된 횟수로 재시도한다. 명시적 해제가 끝내 실패하면 `BackendError`로 반환하여 강제 지정할 수 없게 하며, 시험 스레드 종료가 운영체제의 스레드 소유 등록까지 제거한다. 등록 조합이나 키 값은 진단에 포함하지 않는다.
종료 복구: Windows 관찰기는 별도 종료 이벤트와 완료 채널을 사용한다. 종료 신호 오류를 보존하면서도 완료가 확인되면 worker를 반드시 join하고, 완료되지 않으면 제한시간 뒤 생산 채널을 끊고 타입이 있는 종료 오류로 닫아 무기한 대기하지 않는다. 완료 채널 단절은 worker 종료로 분류하며 join panic을 구조화된 종료 오류로 보존하되 process-wide active flag는 finally-style로 반드시 해제한다. macOS도 같은 단절·join 오류 경계를 적용한다. 컨트롤러 worker도 제한된 수신 대기를 사용해 플랫폼이 sender를 잘못 보존한 경우 종료가 제한시간 안에 끝난다.
키 정체성: Windows 저수준 후크는 virtual key뿐 아니라 scan code와 extended flag를 함께 정규화한다. 따라서 주 키보드 Enter/Equal과 NumpadEnter/NumpadEqual을 구분하고, Num Lock이 꺼진 숫자패드 방향·삽입·삭제 키도 전용 탐색 키와 구분하며 반복 상태를 이 결합 정체성으로 추적한다. 직접 등록 표현과 관찰 결과가 같은 키로 왕복되지 않는 조합은 현재 건강한 비소비 관찰기 경로로만 제공한다.
관찰기 건강: macOS 이벤트 탭이 시간 초과 또는 사용자 입력으로 비활성화되면 callback에서 제한된 세 번만 재활성화를 시도하고 실제 활성 상태를 다시 확인한다. 회복하지 못하면 생산 채널을 끊고 run loop를 종료하며 `ObserverDisabled`를 반환한다. 살아 있는 것으로 표시한 채 조용히 입력을 잃는 상태를 허용하지 않는다.
시작 원자성: Windows와 macOS 모두 process-wide active flag를 rollback guard로 획득한다. sender/키 상태 mutex, native handle, worker 시작 또는 준비 확인 중 어느 단계가 실패해도 guard가 active flag를 되돌려 다음 정상 시작을 막지 않는다. worker 종료와 제한시간 경합은 3상태 원자 handshake로 소유권을 넘겨, 이전 관찰기의 늦은 정리가 새 관찰기의 전역 상태를 지우지 못하게 한다.

[D-033] 선택 텍스트 획득의 클립보드 소유권과 속도 우선 검증 범위
상태: 임시 확정 — 사용자의 2026-08-30 속도 우선 지시에 따른 Task 5 중간 경계
보안 경계: 포그라운드 앱의 정제된 실행 파일 basename 또는 bundle identifier가 사용자 차단 목록과 일치하면 클립보드를 열거나 복사 입력을 보내기 전에 실패 폐쇄한다. 기존 클립보드는 포맷 수 128개, 합계 32MiB 안에서 스냅샷하고 선택 텍스트는 4MiB, 대기는 최대 1초로 제한한다. 합성 복사 뒤 운영체제 clipboard generation/sequence를 소유 세대로 기록하고 복원 직전에도 같은 세대일 때만 복원한다. 사용자나 다른 앱이 중간에 클립보드를 바꿨으면 절대 덮어쓰지 않는다. 경로, 창 제목, 선택 텍스트, 클립보드 데이터는 로그·오류·Debug 출력에 넣지 않는다.
Windows 경계: HGLOBAL로 안전하게 복제 가능한 모든 열거 포맷을 복사하고, bitmap/metafile/palette처럼 다른 소유 규칙을 가진 포맷이 있으면 복사를 시작하기 전에 실패 폐쇄한다. 복원용 메모리는 클립보드를 비우기 전에 전부 할당한다. Ctrl+C 입력은 SendInput으로 제한된 네 이벤트만 보낸다.
macOS 경계: 속도 우선 중간 구현에서는 텍스트 전용 폴백으로 rich clipboard를 손상시키지 않도록 adapter를 명시적 BackendUnavailable로 실패 폐쇄한다. AppKit 다중 pasteboard item 복원은 후속 macOS 실기/CI 검증과 함께 완성해야 하며 지원 완료를 주장하지 않는다.
검증 범위 변경: 원래 RED 테스트 8개를 작성했으나 사용자가 실패 상황 중심 장시간 TDD gate를 즉시 중단하고 happy-path 구현을 우선하도록 지시했다. 테스트 소스는 보존하되 이번 커밋에서는 실행 근거로 사용하지 않는다. Rust 포맷, Windows `cargo check --lib`, diff/기록 검사만 수행하며 전체 회귀와 macOS 실행 통과를 주장하지 않는다.

[D-034] 선택 복사 트랜잭션 정적 검토 보강
상태: 확정 — D-033의 Windows 복원과 입력 소유권 경계를 대체함
원자 복원: `conditional_restore(expected_generation, snapshot)` 포트가 운영체제 클립보드를 연 상태에서 현재 generation을 다시 확인하고, 일치할 때만 비우기와 복원을 수행한다. Windows는 수명이 제한된 message-only owner HWND로 `OpenClipboard`/`EmptyClipboard`/`SetClipboardData` 계약을 충족하고 클립보드를 닫은 뒤 owner를 제거한다. 일치하지 않으면 어떠한 포맷도 변경하지 않는다.
취소 경계: 합성 입력과 최초 generation 소유권 획득 사이에는 async 취소 지점을 두지 않는다. 그 뒤의 모든 정상 오류 경로는 조건부 복원을 동기 완료하고 복원 오류를 우선 반환하며, future 취소는 Drop에서 같은 원자 조건부 복원을 제한시간 안에 시도한다.
입력 상태: Windows 합성 복사는 현재 Ctrl/Shift/Alt/좌우 Win 상태를 읽는다. 이미 눌린 Ctrl은 그대로 사용하고, 간섭 수정 키는 잠시 올렸다가 원래 상태로 복원한다. SendInput이 일부만 수락해도 C/Ctrl key-up과 원래 수정 키 복구 입력을 별도로 시도한다. 키 상태나 입력 내용은 기록하지 않는다.
진단 경계: 클립보드 바이트나 선택 텍스트를 가진 구조체의 Debug는 데이터 대신 포맷 수와 바이트 길이만 표시하며 generation도 숨긴다.

[D-035] 비동기 클립보드 쓰기와 호출 취소 분리
상태: 확정 — D-034의 취소 경계를 구체화함
결정: 선택 캡처 요청은 1개 permit을 획득한 뒤 제한 수명의 전용 worker에게 permit, snapshot, 합성 복사, 최대 1초 generation 관찰, 읽기와 원자 조건부 복원을 모두 넘긴다. 호출 future가 결과 대기 중 취소되더라도 worker와 permit은 남아 트랜잭션을 끝내며, 종료 전에는 다음 캡처가 시작되지 않는다. worker 생성에 실패하면 합성 입력 전에 실패한다. worker 결과 채널이 사라져도 클립보드 트랜잭션은 계속 완료한다. 사용자나 다른 앱의 후속 generation은 D-034의 원자 조건부 복원에서 변경 없이 보존한다.

[D-036] 단축키 설정 저장과 사용자 충돌 해결 경계
상태: 확정
결정: 단축키 녹화 중에는 앱 전역 단축키 발화를 일시 중지하며 완료, 취소, Escape와 화면 해제 모두에서 해제한다. 단일 조합과 최대 4단계 연속 입력을 동일한 정규화 계약으로 저장하고 최대 32개, 고유 ID, 유효한 번역 프로필과 상태기계 제한을 Rust 저장 경계에서 다시 검증한다. 기존 설정 문서는 누락된 단축키 목록을 빈 목록으로 자동 이행한다.
충돌 화면: 실제 운영체제 등록 시험과 현재 프로그램의 공식 카탈로그 일치를 매 편집마다 다시 분석한다. 프로그램명과 기존 기능, 위험 이유를 함께 표시하고 충돌 없는 대체키만 최대 3개 제공한다. 충돌은 기본 저장할 수 없고 `canForce`가 참인 관찰기 대체 경로에서만 별도 경고 뒤 두 번째 확인으로 강제 저장한다. 운영체제 예약, 권한 거부, 잘못된 키와 백엔드 오류는 강제할 수 없다. 엄격한 시작 접두사 advisory는 기존 기능이 함께 실행될 수 있음을 알리되 기본 저장을 허용한다.
연속 입력 확인: 아직 관찰기가 실행 중이지 않으면 설정 분석기가 같은 비소비 네이티브 관찰기를 짧게 시작하고 즉시 정상 종료해 실제 가용성을 확인한다. 이미 실행 중이면 건강 상태를 사용한다. 시작·종료 실패나 접근성 권한 부재를 정상 가용성으로 추측하지 않는다.
차단·개인정보: 사용자가 정제된 Windows 실행 파일 basename 또는 macOS bundle ID와 표시 이름을 추가·삭제할 수 있다. 차단 항목은 선택문 읽기와 팝업 표시를 함께 막는다. 전체 실행 경로, 창 제목, 키 입력, 선택문과 클립보드 내용은 설정·로그·오류에 저장하지 않는다.

[D-037] 빠른 번역 팝업의 단일 창·요청 소유권 경계
상태: 확정
결정: 빠른 번역은 앱 시작부터 숨겨 둔 `quick-popup` 창 하나만 재사용한다. 전역 단축키 발화마다 새 UUID를 만들고 React 작업 경계를 해당 ID로 교체하여 이전 번역 작업을 취소하고 늦은 스트림을 폐기한다. 팝업은 보이는 동안만 always-on-top이며, 고정하지 않은 상태의 포커스 이탈과 Escape에서 닫는다.
배치: Windows는 운영체제 커서 위치와 nearest monitor work area를 물리 픽셀로 읽고 16px inset 안에 560×360 창을 clamp한다. 위치를 얻지 못하는 플랫폼은 현재 모니터 중앙의 안전한 대체 위치를 사용한다.
보안: 차단 목록 확인과 선택문 캡처는 창 표시 전에 수행한다. 차단 앱은 내용 접근과 창 표시가 모두 없고, 캡처 오류는 내용 없는 코드만 전달한다. 원문은 기존 제한 번역 계약의 비신뢰 데이터로만 사용하며 로그·Debug·오류 메시지에 넣지 않는다. 음성은 WebView가 제공하는 설치된 운영체제 음성만 사용하고 외부 음성 서비스로 전송하지 않는다.

[D-038] 단일 상주 컨트롤러와 명시적 정리 종료
상태: 확정
결정: Windows 트레이와 macOS 메뉴 막대는 프로세스당 고정 ID의 Tauri tray 하나로 구성한다. 로그인 시 실행은 설치 앱에서만 Tauri autostart 플러그인으로 변경하고 OS 호출 실패 시 저장값을 바꾸지 않는다. 명시적 종료는 번역 작업과 Codex transport 및 전역키 관찰기를 정리한 뒤 종료한다.
근거: 개발 실행 파일의 자동 시작 등록과 중복 tray/listener를 방지하면서 UI·OS 실제 상태를 일치시키고 사용자 데이터 작업을 안전하게 닫기 위함이다.

[D-039] 이미지 입력과 화면 영역 캡처의 좌표·개인정보 경계
상태: 확정
좌표 계약: 화면 선택의 권위 값은 음수 원점을 허용하는 전역 물리 픽셀 사각형이다. 각 모니터는 전역 물리 bounds, 논리 bounds와 운영체제 유효 scale factor를 함께 제공하며 React pointer의 논리 좌표를 해당 모니터에서 한 번만 물리 좌표로 변환한다. 원본/번역 이미지 안의 OCR 좌표는 유한한 0..=1 정규화 값만 허용한다.
입력 경계: 이미지 경로는 native picker에서만 받고 source는 read-only handle로 읽는다. magic byte로 PNG/JPEG/WebP/TIFF/BMP를 식별하고 입력 50MiB, 80MP, RGBA 해제 크기 200MiB, 요청당 32개를 넘으면 decode 전에 거부한다. EXIF 방향을 적용하되 원본 SHA-256·원래 크기·방향·색상 형식·ICC 존재 metadata를 immutable app-owned copy와 함께 보존하며 원본은 쓰지 않는다.
캡처 수명주기: overlay를 띄우기 전에 모니터 frame을 고정하고 세션 하나만 허용한다. 모니터별 투명 전체 화면 overlay는 같은 전역 물리 선택을 공유하며 완료·취소·창 생성 실패 시 전체 집합을 닫는다. 캡처 결과는 앱 전용 immutable PNG와 내용 없는 job metadata로 다음 OCR 단계에 전달한다.
권한·개인정보: 포그라운드 앱이 사용자 차단 목록에 있으면 화면 접근 전에 거부한다. macOS 화면 기록 권한이 없으면 overlay 전에 typed permission error와 System Settings 위치를 제공한다. 화면/이미지 픽셀, OCR 전 원문, 전체 source/copy 경로와 모니터 외 사용자 식별 데이터는 로그·오류·Debug 출력에 포함하지 않는다.
검증 범위: 사용자의 속도 우선 지시에 따라 frontend production build와 Windows library check만 관문으로 사용했다. Windows 실제 캡처와 macOS 실기는 완료를 주장하지 않고 후속 짧은 실행/CI 검증 대상으로 남긴다.

[D-040] 로컬 OCR·구조화 이미지 번역과 보존적 렌더/내보내기 경계
상태: 확정
OCR 경계: 사용자 이미지 픽셀은 Windows.Media.Ocr 또는 macOS Vision에만 전달하고 네트워크 OCR fallback을 두지 않는다. 공통 결과는 top-left 0..=1 bounds/polygon, NFC text, 0..=1 confidence, angle, direction과 제한된 language tag로 검증한다. Windows 설치 언어 엔진과 macOS accurate recognition/language correction을 사용하며 typed 언어 팩·OS 버전·native 오류 외에 이미지 내용과 경로를 오류에 넣지 않는다.
번역 경계: column/paragraph grouping은 입력 순서와 무관하게 결정적이어야 하고 각 source line ID를 한 번만 소유한다. 블록 `{id,text}` 배열 전체를 기존 제한 Codex 번역 요청의 단일 비신뢰 source 값으로 전달한다. 응답의 누락·중복·unknown ID는 권위 있는 구조화 결과로 사용하지 않으며 URL과 사용자 보호 용어를 원문 그대로 유지한다. 이미지 안의 악성 지시는 번역 데이터일 뿐 명령, 도구, 파일 접근이나 동작으로 해석하지 않는다.
렌더 경계: 원본은 수정하지 않고 expanded text mask 밖 pixel은 건드리지 않는다. 단순 배경만 median fill하고 복잡한 배경은 제한된 interpolation과 경고를 사용한다. OFL Noto Sans와 OS fallback을 cosmic-text shaping에 사용하고 8px 미만으로 줄이지 않으며 영역 밖은 clip하고 overflow를 표시한다.
저장·UI 경계: 결과는 job ID로만 접근하고 WebView가 임의 image bytes나 source path를 저장 명령에 전달하지 않는다. native dialog가 고른 sibling temporary에 encode·sync·decode 검증 뒤 rename하며 기본적으로 기존 파일을 덮지 않는다. UI는 progress/cancel과 원본/번역/나란히 보기, block 수정·가시성·재시도, 경고 포커스를 한국어·영어로 제공한다. 미리보기는 bounded thumbnail이고 export는 원래 해상도를 유지한다.
검증 범위: 사용자 속도 우선 지시에 따라 frontend production build와 Windows library check를 최소 관문으로 사용한다. macOS Vision 실기와 시각적 perceptual acceptance는 후속 CI/실기 단계 전까지 통과를 주장하지 않는다.

[D-041] OOXML 원본 불변·구조화 문서 번역 경계
상태: 확정
입출력: DOCX/PPTX/XLSX source는 read-only bytes와 SHA-256으로 고정한다. 결과는 source sibling의 고유한 새 이름만 사용하고 create-new partial을 flush/sync한 뒤 validation 성공 시 rename한다. 기존 파일을 덮어쓰지 않으며 source hash가 달라지면 결과를 제거한다.
패키지 경계: OOXML ZIP은 traversal, absolute path, encryption, duplicate entry와 제한을 넘는 expansion을 거부한다. quick-xml 0.41(MIT) event copy로 namespace, 속성, run properties와 unknown XML을 유지하고 승인된 local text node만 escape하여 바꾼다. 관계, media, formula, number와 field instruction은 수정하지 않는다.
번역 경계: 문서 segment JSON은 기존 보안 Codex 번역의 단일 비신뢰 source 값이다. 문서 안 문장은 명령으로 해석하지 않고 도구·파일 접근을 허용하지 않는다. 안정 ID와 job-scoped 보호 token을 모두 검증한 batch만 재조립하며 문서 내용, 전체 경로와 번역문은 progress/log/error에 기록하지 않는다.
범위: 이번 milestone은 DOCX/PPTX/XLSX의 사용 가능한 happy path와 reopen validation을 제공한다. PDF는 별도 Task 7, hidden slide/sheet 정밀 scope, Excel style clone/wrap과 실제 Office/macOS visual acceptance는 후속 단계에서 보강하며 현재 통과를 주장하지 않는다.

[D-042] PDF 페이지 분류·로컬 OCR·비파괴 오버레이와 런타임 경계
상태: 확정
파서와 제한: lopdf 0.38.0(MIT)을 사용하고 입력 200MiB, 2,000페이지, 200,000객체, page content 32MiB, 총 텍스트 4M자를 넘으면 발행 전에 거부한다. 암호화/암호 PDF는 `PasswordRequired`로 실패하고 경로·내용을 오류나 로그에 넣지 않는다. 페이지는 20개 비공백 문자와 0.5% text bounds를 기준으로 text/scanned/mixed를 결정하며 사용자 force OCR을 허용한다.
OCR: Windows는 Windows.Data.Pdf, macOS는 PDFKit/CoreGraphics Objective-C bridge로 각 scanned/mixed page를 144DPI(72–300 clamp), 최대 8192px/80MP RGBA로 렌더한 뒤 기존 로컬 Windows.Media.Ocr 또는 Vision 어댑터에 전달한다. 운영체제 렌더러·언어 팩·OCR을 사용할 수 없으면 정상 번역 사본으로 가장하지 않고 typed `OcrUnavailable`로 실패한다.
재조립: 원본 content/resources를 제거하지 않고 translated text를 cosmic-text와 OFL Noto/system fallback으로 raster shape한 XObject overlay로 추가한다. page size·rotation·annotations·attachments·forms를 최대한 보존하고 결과를 재열어 page/box/rotation을 확인한다. 복잡한 배경은 `backgroundApproximation`, 전자서명은 `signatureInvalidated`, 양식은 `interactiveFormPreserved`로 위치와 조치가 명확한 보고를 만든다.
라이선스: PDFium은 다운로드·포함하지 않는다. Windows.Data.Pdf와 PDFKit/CoreGraphics는 각 OS 구성요소이고 lopdf 0.38.0은 Cargo.lock에 고정한다. Noto Sans variable font와 SIL Open Font License 1.1은 설치 번들 resource에 함께 포함한다.

[D-043] PDF 불확실성 fallback·비덮어쓰기 발행·재개 연결점
상태: 확정
추출 경계: ToUnicode/font encoding과 누적 CTM/text matrix로 안전하게 복원할 수 있는 가로쓰기 text operator만 구조화한다. vertical font, clipping, Form XObject, 지원하지 않는 encoding과 replacement glyph는 잘못된 문자열을 번역하지 않고 해당 페이지를 bounded raster OCR로 전환하며 사유를 보고한다. 큰 이미지는 개수가 아니라 페이지 면적 비율로 판정하고 native/OCR block은 동일 좌표계의 IoU로 중복 제거한다.
재조립 경계: CropBox 원점과 rotation을 page/display/OCR 사이에서 명시적으로 변환한다. 복잡·스캔 페이지는 최대 300DPI raster fallback을 사용하고 일반 페이지는 실제 fit 결과를 검사한다. low-confidence OCR, font substitution, background approximation, overflow와 raster fallback은 내용 없는 code와 위치로 경고한다. annotations/forms/attachments 보존 선택과 재열기 구조 검증을 결과 발행 전에 적용한다.
발행 경계: 결과 partial은 create-new handle에 쓰고 flush/sync한 뒤 동일 volume hard link로 존재하지 않는 최종 이름에만 원자 발행한다. 오류 시 이번 작업이 만든 partial 또는 새 output만 제거하며 source나 기존 결과는 건드리지 않는다.
진행·재개: inspect/extract/ocr/translate/reflow/save/validate/completed 단계와 결정적 unit ID를 event/checkpoint 경계로 제공한다. 취소는 OCR·재조립·저장 사이에도 검사한다. 내구 resume는 암호화 JobStore를 도입하는 history/recovery milestone이 권위 저장소를 제공할 때 `resumed_from_stage` 연결점을 사용하며, 그 전에는 프로세스 간 재개 완료를 주장하지 않는다.

[D-044] PDF page spool·순차 render 검증·typed document event 계약
상태: 확정
메모리 경계: PDF 페이지 bitmap은 `DocumentPlan`에 RGBA로 누적하지 않는다. app data 아래 UUID job root의 `pages/page-NNNNN.png` 상대 ref만 checkpoint에 보유하고, OCR·배경 판정·재조립은 한 페이지씩 decode 후 해제한다. job cleanup은 예상 root의 32자리 UUID 자식인지 확인한 뒤 현재 job 폴더만 제거한다.
시각 경계: 일반 text page도 OS renderer 결과에서 block 영역을 제한 sampling해 중앙 배경색과 색 변화 비율을 구한다. 균일 영역은 추정색 text overlay, 복잡 영역·큰 이미지·스캔 page는 최대 300DPI page raster fallback을 사용한다. 발행 결과는 모든 페이지를 72DPI로 순차 렌더해 CropBox/rotation 기준 크기를 확인하고, EmbeddedFiles는 name tree leaf 항목 수로 검증한다.
이벤트·재개: `document-job` 하나가 progress checkpoint, warning, completed report와 sanitized failed code/location을 tagged event로 전달한다. checkpoint는 source fingerprint, stable page/batch unit ID, 상대 raster refs와 content-free translated result refs를 포함해 암호화 JobStore가 그대로 저장·rehydrate할 수 있다. 실제 영구 저장은 후속 history/recovery milestone 전까지 주장하지 않는다.

[D-045] PDF adaptive raster·spool quota·retention ACK와 결과 위치 계약
상태: 확정
래스터 품질: 일반 text page를 144DPI로 제한 sampling한 결과가 복잡하면 그 페이지만 300DPI hard cap으로 재렌더한다. spool에는 최종 page PNG만 남기고 loader/writer 모두 페이지 64MiB, job 8GiB와 2,000페이지 계약을 사용한다. OS free-space가 예상량과 256MiB 안전 여유보다 작으면 rendering 전에 `LimitExceeded`로 중단한다.
검증 좌표: Windows.Data.Pdf와 PDFKit bridge가 반환하는 bitmap width/height가 권위 값이다. 결과 검증은 같은 renderer로 source/output page를 72DPI 순차 렌더해 직접 비교하며 rotation에 따른 swap을 다시 추측하지 않는다. PDF box/rotation metadata는 lopdf 구조 검증으로 별도 비교한다.
재개 보존: batch 성공 뒤 checkpoint의 stable unit/cursor와 누적 translated-result refs를 갱신하고 reflow/save/completed까지 전달한다. 암호화 저장소는 ref-to-TranslatedSegment resolver로 rehydrate한다. retryable auth/network/quota 실패의 job root는 retention request에 명시적 ACK가 있을 때만 넘기며 ACK 부재·취소·성공·secret mode는 항상 정리한다.
화면 위치: 보고 위치가 page/slide/cell로 정확히 parse되는 형식은 결과 위치 preview selection과 focus를 바꾼다. 정확한 target이 없으면 파일 위치 이동을 주장하지 않고 보고 항목 focus만 제공한다. 결과 파일 열기는 별도 action이다.

[D-046] Output-derived preview·source-rerender resume·plaintext-free retention handoff
상태: 확정
결과 미리보기: 보고 위치 미리보기는 UI 문자열로 만들지 않는다. backend가 발행된 output을 다시 열어 PDF page OS-render PNG, PPTX slide text/shape geometry, XLSX adjacent cell grid/value 또는 DOCX part context를 bounded sanitized payload로 반환한다. 정확히 해석할 수 없는 위치는 보고 항목 focus만 제공한다.
재개: encrypted JobStore가 제공한 checkpoint와 ref resolver만 입력으로 받는다. source fingerprint, completed batch prefix와 post-batch marker를 검증한 뒤 completed batch cursor부터 재개하며 reflow/save/validate/completed checkpoint도 cursor를 보존한다. PDF raster ref는 복원하지 않고 원본을 다시 렌더한다.
spool: plaintext page PNG는 Tauri per-user app_data 아래 UUID root에만 두고 directory/file ACL 또는 0700/0600을 best effort로 적용한다. ACK·성공·secret·취소·모든 실패에 관계없이 canonical app-data root의 현재 UUID child만 즉시 삭제한다.
retention: retryable failure는 one-time nonce와 content/path 없는 전체 checkpoint를 알린다. future history JobStore는 같은 job/token의 in-process translated-ref payload를 암호화 저장한 뒤 restricted opaque receipt로 ACK한다. unmatched/replayed ACK는 거부하고 begin은 stale request/receipt를 제거한다. Token, receipt, event와 log에는 문서 내용이나 경로를 넣지 않는다.

[D-047] 결정적 문서 세그먼트·XLSX 실제 위치·backend-only 재개·제한 Office preview
상태: 확정
세그먼트 ID: DOCX/PPTX/XLSX/PDF의 번역 세그먼트 UUID는 원문 문자열, 파일 경로 또는 작업 UUID를 직접 사용하지 않는다. 검증된 source SHA-256 fingerprint와 format, OOXML part 또는 PDF page, 안정 logical location/index를 UUIDv5 입력으로 사용한다. 동일 source 재검사는 동일 ID를 내고 source fingerprint가 달라지면 prefix resume를 거부한다.
XLSX 위치: workbook relationship으로 worksheet part와 실제 sheet name을 연결하고 shared-string index가 소비되는 모든 cell을 수집한다. 번역 segment/report에는 첫 소비 cell의 `sheet:<name>/cell:<A1>`과 총 사용 수를 기록하며 inline string도 소유 cell을 기록한다. 소비되지 않는 shared string은 실제 결과 위치가 없으므로 번역·경고 대상에서 제외한다.
재개 보안: 이 항목은 D-046의 공개 retention event/ACK 구상을 대체한다. WebView IPC는 plaintext `translatedResults`, retention token, persistence ACK를 받거나 반환하지 않는다. 공개 resume 입력은 제한된 opaque encrypted-record ID뿐이고 선택한 source는 기존 source path 인자로 다시 fingerprint 검증한다. retryable payload는 backend-only listener가 metadata를 받고 동기적으로 one-shot payload를 가져가는 경우에만 메모리에 남긴다. listener가 없거나 거부하면 즉시, 그 밖에는 60초 TTL과 begin/finish/cancel/global purge에서 번역문과 key를 zeroize해 제거한다. 내구 재개는 암호화 JobStore consumer가 설치될 때만 가능하다.
미리보기 ZIP: Office 결과 미리보기는 파일 전체를 메모리에 읽거나 전체 entry를 해제하지 않는다. 중앙 디렉터리에서 entry 수, 안전 경로, 중복, 암호화, 선언 크기와 압축비를 검사하고 DOCX target part, PPTX target slide/presentation, XLSX workbook/rels/target sheet/optional shared strings만 스트리밍한다. 실제 해제는 entry 16MiB, 요청 합계 64MiB를 넘으면 typed preview limit 오류로 중단하며 화면 grid/shape/context 수 제한은 계속 적용한다.

[D-048] 운영체제 키 기반 단일 암호화 저장소와 실패 폐쇄
상태: 확정
결정: history/recovery는 OS credential store의 `com.smartcat.translate`/`local-data-key` 32바이트 키와 AES-256-GCM v1을 공유한다. write마다 fresh nonce와 `table:row:column` AAD를 사용한다. 키링이 없거나 잠겼으면 평문 fallback하지 않고 Codex token은 저장하지 않는다.

[D-049] canonical 옵션 snapshot이 문서 재개의 load-bearing 경계
상태: 확정
결정: durable job은 source/target, 실제 profile, model, quality, 적용 glossary와 전체 format/output option을 canonical JSON으로 암호화하고 SHA-256 hash를 보유한다. resume는 source fingerprint와 snapshot/caller option hash가 모두 일치할 때만 허용하며 설정이 달라지면 새 작업만 허용한다.

[D-050] 시크릿·보존·정리 공통 lifecycle
상태: 확정

[D-052] 진행 checkpoint와 임시 데이터의 단일 소유권

[D-055] 완료 전이와 cleanup metadata 원자성
상태: 확정
결정: JobStage Completed는 Save에서만 전이할 수 있고 active stage의 Cancelled/Failed 및 Paused 복귀 규칙은 유지한다. cleanup pending metadata는 같은 private root의 고정 temp를 create_new로 열어 write/flush/sync_all한 뒤 플랫폼 원자 replace하고 parent directory를 best-effort sync한다. 손상된 primary를 빈 목록으로 대체하지 않고 valid temp를 우선 복구하거나 UUID job root를 pending으로 재구성한다.

[D-056] cleanup 상태의 process-wide 직렬화와 보수적 합집합
상태: 확정
결정: canonical private root별 CleanupService는 process-wide registry의 단일 Arc<Mutex<State>>를 공유하며 pending load/retry/mutate/persist 전체를 그 잠금 아래 수행한다. startup pending은 valid primary, valid temp, 실제 UUID direct-child의 합집합이고 temp 오류 흔적은 경고 상태로 유지한다. 어떤 valid UUID도 metadata 선택 과정에서 버리지 않는다.

[D-057] 릴리스 전용 updater 구성과 사용자 2단계 승인
상태: 확정
결정: committed local/dev Tauri config에는 updater endpoint/public key/artifact 생성을 두지 않고 명령도 실패 폐쇄한다. 보호된 GitHub `release-signing` Environment에서만 실제 `GITHUB_REPOSITORY`와 Minisign 공개키를 ephemeral checkout에 넣는다. 확인 응답은 version/notes/date/size와 15분·버전 결합·1회 token을 만들고, 사용자의 다운로드 승인 뒤 Tauri가 전체 payload 서명을 확인한다. 별도 재시작 확인 뒤에만 설치하며 background check/download/install/restart와 silent rollback은 없다.

[D-058] 비밀 없는 다중 플랫폼 릴리스 관문
상태: 확정
결정: Windows x64 MSI/NSIS, macOS 15 Intel app/DMG, macOS 14 ARM app/DMG를 고정 pnpm/Rust로 각각 만들고 frontend/Rust/records/privacy/runtime asset 관문 뒤에만 tauri-action을 실행한다. Windows PFX와 Apple Developer ID/notarization 및 updater private key는 보호 Environment secret으로만 읽고 임시 cert/keychain을 제거한다. repository는 private key/certificate를 생성하거나 저장하지 않는다. 모든 leg 뒤 draft release에 checksums, npm/Cargo SBOM, bundled licenses, run/commit provenance, attestation과 updater manifest를 묶는다. PR artifact는 `UNSIGNED`로만 표시한다.

[D-059] 비파괴 acceptance와 미검증 플랫폼 표기
상태: 확정
결정: 로컬 prerelease 스크립트는 OS temp 아래 disposable app/test-data root와 MSI administrative image 또는 read-only DMG copy만 사용한다. 사용자 Documents는 삭제·이동하지 않고 Windows에서는 전후 hash가 같아야 한다. 실제 macOS Intel/ARM installed-app smoke, protected signing secret, 공증과 release publication은 CI/사용자 환경에서만 검증할 수 있으므로 실행 전에는 통과로 기록하지 않는다.

[D-060] publication fix round의 태그·LKG·플랫폼 신뢰 관문
상태: 확정
결정: protected environment보다 먼저 exact refs/tags app-vSEMVER와 package/Cargo/Tauri 버전을 일치시킨다. Intel runner는 macOS 15 Intel을 사용한다. pending update는 이전/대상 버전과 installer refs를 남기며 대상 버전 UI hydration/main-window ready 뒤에만 LKG로 승격한다. restart consent는 backend가 install token/version에 결합해 1회 소비한다. release package는 updater key-pair canary, Windows Authenticode Valid 또는 macOS codesign/spctl/stapler, CI-only disposable installed-app readiness, 실제 dependency license texts를 모두 통과한 뒤에만 draft publish 단계로 간다. 사용자 지시에 따라 새 negative/E2E test는 추가하지 않고 이 미작성 범위를 verification gap으로 남긴다.

[D-061] updater v2 자산·실제 secure store acceptance·완전한 LKG 관문
상태: 확정
결정: Windows update feed는 Tauri v2가 만든 adjacent signature의 `.nsis.zip`을 우선하고 없을 때 `.msi.zip`만 사용하며 raw exe/msi를 거부한다. signed binary에는 acceptance env, app-data override, 고정 key/ready marker를 넣지 않는다. 실제 launch acceptance는 CI=true와 GITHUB_ACTIONS=true인 일회용 runner에서만 OS Credential Manager/Keychain과 기본 app data를 사용하고 실패 폐쇄를 확인한다. LKG는 lifecycle/account/settings/privacy/history/recovery load와 stable timer가 성공한 뒤 backend state write/clear가 모두 성공한 경우에만 1회 확정한다. license expressions는 maintained SPDX parser, SBOM은 official CycloneDX 1.6 validator를 통과해야 하며 release-assets의 latest manifest가 checksum·attestation·upload보다 먼저 생성된다.

[D-062] acceptance cleanup의 관찰 기반 소유권
상태: 확정
결정: CI/GITHUB_ACTIONS 표시는 기존 데이터 삭제 권한이 아니다. cleanup handler보다 먼저 appDataOwned, installedByThisRun, copiedByThisRun을 false로 만들고 기존 exact app data, OS credential item과 설치 흔적을 확인한다. precondition 뒤 이 실행이 새 exact canonical app data를 실제 관찰한 때만 소유하며, uninstall과 app-copy 삭제도 각 실행이 성공적으로 만든 경우만 허용한다. 기존 항목이 하나라도 있으면 소유권은 false인 채 실패하고 아무 기존 app/key/install data도 삭제하지 않는다.
