SmartCAT Translate 프로젝트 기록
================================

[2026-08-28] 프로젝트 설계 시작

목표
- Windows와 macOS에서 동작하는 로컬 번역 데스크톱 앱을 만든다.
- DeepL과 유사한 전체 창과 작은 빠른 번역 창을 제공한다.
- 사용자의 ChatGPT 계정을 공식 Codex App Server 인증으로 연결한다.
- 텍스트, 이미지, 화면 캡처, DOCX, PPTX, XLSX, PDF를 번역한다.
- 문서 번역 결과는 원본 서식과 배치를 최대한 유지한 새 파일로 저장한다.
- 계획, 명세, 결정, 변경, 테스트 결과를 프로젝트 내부에 계속 기록한다.

현재까지 승인된 설계
1. 문서 형식은 DOCX, PPTX, XLSX, PDF를 모두 지원한다.
2. 원본 파일은 덮어쓰지 않고 번역 결과를 새 파일로 저장한다.
3. 이미지와 화면 캡처는 번역문을 원래 위치에 배치한 이미지와 원문/번역문 비교 창을 모두 제공한다.
4. 원문 복사, 번역문 복사, 번역 이미지 저장을 모두 제공한다.
5. 단축키 충돌 시 기본적으로 등록을 막고 충돌 가능 프로그램과 기능을 표시한다.
6. 사용 가능한 대체 단축키를 자동 추천하며, 명시적 선택 시 경고 후 강제 등록할 수 있다.
7. DeepL형 전체 창, 작은 번역 팝업, 화면 캡처 결과 창의 UI 방향을 승인했다.
8. 기술 기반은 Tauri 2 + React + TypeScript + Rust로 확정했다.
9. GitHub Actions로 Windows와 macOS 빌드를 생성한다.
10. 기존 Codex 설치와 로그인 상태를 우선 사용하고, 없으면 앱 전용 공식 Codex를 설치한다.
11. 인증과 번역은 공식 Codex App Server를 사용한다.
12. 문서 본문, 표, 텍스트 상자, 머리글/바닥글, PPT 발표자 노트, Word 각주/미주를 번역한다.
13. 댓글, 메모, 숨김 내용, 시트 이름 등은 옵션으로 제공한다.
14. 수식, URL, 파일 경로, 코드, 변수명, 보호 용어는 번역하지 않는다.
15. 번역 결과 저장 후 구조 손상과 요소 개수를 자동 검사한다.
16. 빠른/균형/정밀 번역, 언어쌍 즐겨찾기, 단축키별 언어쌍, 용어집을 제공한다.
17. 기본 번역 설정은 자동 감지 → 한국어, 균형 번역, 자연스러운 문체다.
18. 번역 기록은 기본 30일간 로컬 암호화 저장하며 시크릿 번역을 제공한다.
19. 인증 정보와 번역 원문은 개발 기록 및 오류 기록에 남기지 않는다.
20. GitHub Releases에서 새 버전을 확인하고 변경 내용을 보여준 뒤 사용자 동의를 받아 설치한다.
21. 오류 발생 시 단계별 상태를 보존하고 재시도, 재로그인, 중단 후 복구를 지원한다.
22. 원본 불변성, 문서 구조, 서식 보존, 개인정보 비기록 여부를 자동 검증한다.
23. Windows와 macOS 설치 파일을 GitHub Actions에서 만들고 사전 공개판을 거쳐 안정판을 배포한다.

[2026-08-28 14:08 Asia/Seoul] Codex App Server JSONL 전송 계층

구현
- 검증된 `ResolvedRuntime`이 소유한 초기화 완료 라이브 세션에서 같은 입출력 채널을 인계받아, 실행 경로를 다시 탐색하거나 프로세스를 재실행하지 않는 JSONL 전송 계층을 추가함.
- 단일 writer 작업이 요청 하나를 JSON 한 줄로 기록하고, reader 작업이 응답 ID별 대기 요청과 서버 알림을 분리해 전달하도록 구현함.
- 동시 요청 ID를 원자적으로 할당하고, 응답 순서가 바뀌어도 올바른 요청으로 전달하며, 취소된 요청의 대기 항목을 자동 제거함.
- 프로세스 종료와 명시적 종료 시 모든 대기 요청을 안전한 종료 오류로 해제하고 `runtime/exited` 알림을 정확히 한 번만 발행함.
- 잘못된 JSON, 알 수 없는 메시지와 응답 ID는 다음 정상 응답을 방해하지 않으며, 알려진 요청의 손상된 응답은 안전한 프로토콜 오류로 종료함.
- 서버 오류의 메시지·데이터, 원문·번역문, 토큰과 전체 경로를 오류 문자열이나 내부 로그에 포함하지 않고 숫자 오류 코드만 노출함. 알림의 `Debug` 출력에서도 매개변수를 숨김.
- 입력 JSONL 한 줄에 8 MiB 상한을 두어 줄바꿈 없는 비정상 입력으로 인한 무제한 메모리 증가를 차단함.

- 텍스트와 OCR block은 기존 구조화 Codex 번역 경계에서 안정 ID와 보호 token을 검증한다. 원본 페이지 content stream, 이미지·vector resource, CropBox/MediaBox, rotation, link·annotation·form을 제거하지 않고 각 번역 block을 OFL Noto/system fallback으로 shaping한 raster overlay로 추가한다. 원본 PDF는 read-only hash로 재확인하고 결과는 고유한 sibling partial을 재열기 검증한 뒤 새 경로로만 발행한다.
- 전자서명은 번역 사본에서 유효하지 않음을, 양식은 보존하지만 필드 값은 번역하지 않음을 보고한다. 배경 근사, OCR, overflow, 서명·양식 위험을 page/block 위치로 표시하며 문서 내용과 전체 경로는 event/log/error에 넣지 않는다.
- 한국어·영어 문서 화면을 DOCX/PPTX/XLSX/PDF 공통으로 확장했다. 원문/대상 언어, 계정 모델, 프로필·용어집, comments/notes/hidden/wrap, PDF fit/OCR/annotation, native 출력 폴더, format badge, 단계 진행·취소·재시도, 결과 파일·폴더 열기와 위치별 위험 보고를 제공한다. 전체 경로는 사용자가 별도 details를 펼친 경우에만 표시한다.

속도 우선 검증과 라이선스
- 사용자 지시에 따라 새 실패 테스트·실패 주입·전체 회귀·장시간 패키지 빌드는 수행하지 않았다. 프런트엔드 `pnpm build`가 통과했고 D 드라이브 공유 target의 Windows `cargo check --lib`가 통과했다.
- PDF parser/writer는 lopdf 0.38.0(MIT), Windows renderer는 운영체제 Windows.Data.Pdf, macOS renderer는 운영체제 PDFKit/CoreGraphics를 사용한다. PDFium 바이너리는 포함하지 않는다. 래스터 글자 shaping에 포함하는 Noto Sans variable font와 SIL OFL 1.1 라이선스는 번들 resource로 함께 보존한다. Windows/macOS PDF 실제 시각 smoke와 서명·양식 상호작용 실기는 후속 acceptance 전까지 통과를 주장하지 않는다.

[2026-08-31] 문서 번역 Tasks 7–8 검토 보강 — PDF 좌표·OCR·저장·진행 경계

구현
- lopdf의 font encoding/ToUnicode 해석과 text/graphics matrix 누적을 사용해 Tj/TJ/작은따옴표/큰따옴표 연산자의 advance와 CropBox 원점·회전을 반영했다. vertical font, clipping, Form XObject와 해석할 수 없는 encoding은 추측 번역하지 않고 페이지 래스터 OCR로 전환하며 사유를 경고한다.
- 큰 이미지 여부를 페이지 면적 비율로 판정하고 native/OCR 좌표의 교차 비율로 중복 block을 제거한다. OCR 좌표는 CropBox와 회전을 역변환하며 복잡·스캔 페이지는 300DPI 한도 안의 전체 페이지 래스터 재조립을 사용한다. 낮은 OCR 신뢰도, 글꼴 대체, background 근사와 text overflow를 페이지·block 경고로 보고한다.
- PDF partial은 create-new로 열어 flush/sync한 뒤 hard-link 기반 비덮어쓰기 발행을 수행한다. 검증·발행 실패 시 partial을 제거하고, 발행 뒤 검증 실패 시 새 결과만 제거한다. 원본은 hash 재확인과 read-only 계약을 유지한다.
- sourceLanguage와 품질 선택을 실제 번역 profile에 반영하고, 아직 구현하지 않은 hidden/wrap 옵션은 화면에서 비활성화해 계획 기능임을 명시했다. native drag/drop, 경고 필터·200개 제한, 한국어 경고 설명과 결과/보고 위치 열기를 공통 문서 화면에 연결했다.
- OCR·reflow·save에도 취소 확인을 추가하고 inspect/extract/ocr/translate/reflow/save/validate/completed의 typed progress와 warning/completed/failed job event를 제공한다. job·단계별 결정적 unit ID와 `resumed_from_stage` 연결점은 구현했으며 암호화 JobStore 기반 내구 resume는 다음 history/recovery milestone 의존성으로 남겼다.

속도 우선 검증과 제한
- 새 실패 시험, 실패 주입, 전체 회귀와 실제 PDF 장시간 smoke는 실행하지 않았다. 변경 Rust 파일 rustfmt와 프런트엔드 production build가 통과했고, 보강 중 D 드라이브 공유 target의 Windows `cargo check --lib`가 10.56초에 통과했다. 마지막 소규모 좌표·경고 보강 뒤에는 사용자 지시에 따라 같은 장시간 관문을 반복하지 않았다.
- Windows/macOS 실제 시각 비교, macOS bridge 실기, page anchor 직접 이동과 시스템에 없는 CJK glyph는 후속 packaged acceptance 대상으로 남긴다.

[2026-08-31] 문서 번역 Tasks 7–8 검토 보강 2 — bounded spool·렌더 검증·재개 payload

- OCR location의 x,y,w,h,confidence 다섯 값을 모두 검증해 스캔·혼합 페이지 block과 낮은 신뢰도 경고가 재조립까지 유지되게 했다.
- 전체 문서 RGBA를 메모리에 쌓지 않고 앱 전용 job root의 결정적 상대 PNG ref로 페이지를 spool한다. 렌더·OCR·재조립은 한 페이지씩 decode하고 drop하며 완료·취소·실패 뒤 UUID job root만 경로 확인 후 제거한다.
- 일반 text page도 렌더 sampling으로 번역 영역 배경의 중앙색과 복잡도를 판정한다. 균일 배경은 추정색 overlay를 사용하고 복잡한 배경은 bounded page raster fallback을 사용한다. 결과 PDF도 페이지를 순차 렌더해 크기·회전 결과를 확인하고 EmbeddedFiles name tree의 실제 항목 수를 비교한다.
- 진행·경고·완료 report·실패를 단일 `document-job` typed event로 통합했다. checkpoint는 source fingerprint, stable page/batch unit ID, sanitized raster ref와 translated-result ref를 직렬화하며 같은 fingerprint의 payload를 plan에 다시 연결할 수 있다.
- 보고서 경고마다 고유 DOM anchor와 focus/scroll 이동을 제공하고 결과 파일 열기는 별도 action으로 유지한다.

검증
- rustfmt 통과, `pnpm build` 통과(59 modules, 711ms), D 공유 target `cargo check --lib` 최종 통과(10.10s), diff/records 검사를 사용했다. 첫 Rust 검사는 이동된 PathBuf 한 건만 발견했고 borrow로 고친 뒤 동일 최소 검사가 통과했다. 새 실패·장기·전체 회귀·실제 PDF smoke는 실행하지 않았다.

[2026-08-31] 문서 번역 Tasks 7–8 검토 보강 3 — adaptive 300DPI·spool quota·결과 위치·retention ACK

- 144DPI로 렌더한 일반 text page의 block 배경 변화가 복잡하면 그 page만 최대 300DPI로 다시 렌더하고 spool에는 고해상도 결과 하나만 저장한다.
- spool은 최대 2,000페이지, 페이지 PNG 64MiB, job 합계 8GiB로 제한하고 시작 전에 예상 공간과 OS 여유 공간을 확인한다. 가능한 Windows 환경에서는 D:\SmartCATTranslateData를 우선하고, 각 write 후 실제 파일·합계 크기를 재검사한다.
- 결과 렌더 검증은 회전 폭·높이를 추측하지 않고 같은 OS renderer로 원본과 결과를 각각 72DPI 렌더해 bitmap dimensions를 비교한다. CropBox와 rotation metadata는 기존 lopdf 재열기 검증에서 별도로 비교한다.
- 보고 위치는 PDF page, PPTX slide, 명시된 XLSX cell을 parse해 작업 화면의 결과 위치 preview를 갱신하고 해당 focus target으로 이동한다. 정확한 target이 없는 DOCX/XLSX 위치는 결과 문서를 연다고 오해시키지 않고 ‘보고 항목으로 이동’으로 표시한다.
- 성공한 번역 batch 직후 누적 encrypted-result ref checkpoint를 emit하고 reflow/save/completed까지 유지한다. 외부 암호화 JobStore가 retryable auth/network/quota 실패의 retention request를 250ms 안에 ACK한 경우만 job root를 넘기며 ACK 부재, 사용자 취소, 성공과 secret mode는 항상 root-confined cleanup한다.

검증
- rustfmt 통과, 최종 `pnpm build` 통과(59 modules, 759ms), D 공유 target `cargo check --lib` 통과(7.67s), records/diff 검사를 사용했다. 첫 Rust 검사에서 spool writer PathBuf borrow 한 건을 고친 뒤 최종 검사가 통과했다. 새 실패·장기·전체 회귀·실제 PDF smoke는 실행하지 않았다.
